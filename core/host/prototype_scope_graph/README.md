# 子流程范围与反馈原型

问题：用户通过明确的包列表、子流程边界、节点和端口反馈，能否表达逐项筛选、全局筛选以及固定或更新参考的两轮计算？

这是可丢弃的逻辑原型。双击 [index.html](index.html) 即可运行。页面支持添加、移除、移动普通节点，进入子流程边界，逐条断开和连接端口，以及查看全部相关包、参数、调用和各轮结果。

同一纯逻辑的命令行演习：

```sh
node core/host/prototype_scope_graph/replay.cjs --write
```

`replay.cjs` 直接提取 HTML 中的 `prototype-logic` 脚本，执行少量引导演习并写入 [evidence.json](evidence.json)。没有另外实现一套演算逻辑，也没有测试套件或模型调用。

## 实际图与边界

每条边传递明确、有序的包 ID 列表。解释器按实际边的依赖调度节点；`Map` 将指定输入列表逐包传入同一子图，其他明确输入直接传入；`Repeat` 重复子图，并仅按用户配置的反馈端口替换下一轮输入。

逐项方案：

```text
Repeat body
  items → Map [ item → Generate → Evaluate → Filter(limit=1) ]
                 reference ────────────┘
        → Collect → Split → nextItems
                   └──────→ result
```

全局方案：

```text
Repeat body
  items → Map [ item → Generate → Evaluate ]
                 reference ────────────┘
        → Collect → Filter(limit=2) → Split → nextItems
                            └──────────────→ result
```

这里的 Collect、Filter、Split 都是解释其格式的模块节点。载体不拆解科学对象，不读取候选的模板、父子关系或分数。`interpret()` 不调用包内容读取接口；`modules()` 才拥有包解析与科学操作。

两种方案只有节点所在子图、连线和明确筛选参数不同。解释器没有“逐模板模式 / 全局模式”分支。图编辑中的“移入/移到”便捷按钮修改这些实际节点和边；手工移入边界则移除原连接，等待用户明确接线。

固定参考保留 Repeat 的原始明确输入。更新参考额外连接 `nextReference → reference`；`nextReference` 来自一个明确的“取选中列表第 1 项作参考”节点。独立导入对象经单独评价节点加入 Collect；其输入不需要生成关系。

## 演习结果

教学数据按明确的“位置与参考距离”计算分数。每个输入生成两个模拟候选；这些数值便于独立手算范围差异。

| 现场执行 | 第一轮选中 | 第二轮选中 |
|---|---|---|
| 每项内筛选 1 个 | A.1、B.1 | A.1.1、B.1.1 |
| 汇总后筛选 2 个 | A.1、A.2 | A.1.1、A.1.2 |
| 汇总后筛选，参考显式反馈 | A.1、A.2 | A.1.2、A.2.1 |
| 加入独立导入对象 | 独立对象、A.1 | 独立对象.1、独立对象.2 |
| 非蛋白格式文字变换 | red!、blue! | red!!、blue!! |

另一次演习通过用户可达的“断开筛选输入”操作产生缺口，运行指出 `筛选: 输入端口 items 尚未连线。`，恢复连接后可继续运行新计算。

真实评价回放使用 [评价原型的实际交付](../../../modules/filtering/prototype_evaluation_handoff/evidence/collection.json)，在 HTML 中嵌入原始 JSON。所选评价为原始 1PGA A 链、完整区域、TM-align、按参考长度归一化的 TM-score；阈值 ≥ 0、降序、数量上限 1。页面实际运行集合合并、评价唯一匹配、筛选和按对象拆分，选中 `feedback-candidate-1`（0.8263003040517922；另一候选为 0.24736964768578332）。“真实记录”选择器可切换[第二轮实际交付](../../../modules/filtering/prototype_evaluation_handoff/evidence/round2/collection.json)，使用同一图与筛选函数，选中 `feedback-round2-candidate-2`（0.6137247185464406；另一候选为 0.6120604009701297）。两轮记录分别回放；页面不执行模型或真实循环。结构文件交付与独立消费由评价原型执行；此页仅回放评价记录，不声称已复制结构文件。

## 回答与后续实现决定

明确列表、子流程边界和端口反馈足以表达本次演习的范围差异，无需由载体读取模板关系。科学集合包含多个对象时，进入逐包处理前需要显式的拆分节点；一包与一对象不是同一概念。

下一轮模板准备仍需明确的编辑模块。本页教学生成直接消费带数值的对象，仅用于确认编排范围；真实结果转模板与真实第二轮计算由相邻科学原型处理。

需要在实现中落实的最小信息是：子图输入和输出端口、逐项输入端口及绑定、重复次数、反馈端口连接、当前轮次和子调用位置。每轮原始输入与结果均可定位。取消、交付和续算由 [嵌套续算原型](../prototype_nested_resume/) 单独回答。
