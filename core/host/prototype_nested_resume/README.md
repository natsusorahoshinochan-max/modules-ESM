# 嵌套位置与续算原型

可丢弃原型。问题：轮次、逐项子流程、节点及节点内请求怎样定位；部分成功、取消、依赖等待和指定旧运行续算如何交接？

## 入口

- 双击 [index.html](index.html)：单文件、内存状态演习。自由操作及三个引导场景覆盖取消、工具失败和完整运行。
- 仓库根目录执行 `python3 core/host/prototype_nested_resume/run.py`：调用真实载体 API，创建名为 `PROTOTYPE-nested-resume-wipe-me-*` 的独立临时目录，执行实际文件接收与读取。控制目录和 scratch SQLite 都在该目录；脚本结束保留它供检查，终端输出具体路径，可在检查后删除。
- [实际证据](evidence/actual-host-run.json)：本次调用、前后状态、公开输入与固定参数、实际交付文件、逐项核对。
- [按钮逻辑演练](evidence/html-reducer-rehearsal.json)：直接执行页面纯状态逻辑的三个引导场景，逐步保留动作及状态；浏览器界面验收单独记录。

## 演习范围

输入是此前真实 ESM3 生成的两条 58 位序列，来自 `modules/esm3/prototype_file_input/evidence/generation.json`，由本演习明确选为历史输入。本轮的工具只复制这些文件，集合模块只合并显式输入；未进行模型计算或科学评价。

`demo_module.py` 只导入公共模块接口。脚本通过 `Workbench.install/configure/create_project/create_input/save_project/start/cancel_run/continue_run/get_run/package` 操作 scratch 项目。每次交付实际写文件，成功接收后通过数据包读取。续算通过公共 `Previous` 接回累计成果和模块私有请求完成信息。

原型外层将一项两轮流程明确展开为无环图，并为普通随机调用 ID 单独记录 `root/repeat/round:1/map/item:1/copy` 等显示位置。载体调度只使用 ID、端口、数据包、依赖和状态。轮次位置没有进入文件内容、科学对象身份或摘要计算。

## 结论

两个实际场景各 14 项核对通过：

1. 取消场景：独立分支和第 1 项先完成；第 2 项的两个请求只完成第一个时，脚本模拟用户调用公开取消入口。已成功文件仍可读取，汇合及第 2 轮均未调用。
2. 失败场景：公开轻量工具调用在第 2 个请求临时不可用；第 2 项停止，汇合和第 2 轮被标为依赖阻塞。随后执行的独立分支成功。临时故障由演习开关明确触发，未构造科学坏数据。
3. 两场景都在停止后修改当前画布参数，再明确继续旧运行的第 2 项。续算只执行请求 2，跳过已经成功的请求及节点，沿用旧输入、旧工具和旧计算参数。
4. 两项完整成功后，汇合才接收它们的输出。第 2 轮读取显式反馈连线的汇合包。每场景最后从载体包实际读取了 3 个 FASTA 文件。

由此可以沿用现有固定调用及文件交付边界：外层定位到某个运行及调用，模块内部定位到未完成请求。模块返回累计结果；载体只在整个节点成功后开放依赖。

## 实现仍需回答的范围

现有后端只执行无环图，尚无原生子流程或轮次调度。本原型手工展开有限两轮，后续实现需要将显式子流程范围映射到这些普通调用，同时保留各轮显示位置。

取消是整次运行行为：未启动的独立节点也会取消。取消场景中的独立分支已在取消前完成；只有失败场景验证了故障之后独立分支继续。生产后端将取消后的未启动下游记为 `cancelled`，失败依赖后的下游记为 `blocked`，两者在证据中分别保留。

现有续算入口要求选中节点曾实际开始且尚未完成。尚未启动的节点本身不能直接选择续算；本次演习从已开始的批次恢复，再由其成功驱动等待中的下游。

尚未验证并行子流程、跨进程崩溃恢复、真实长模型调用的取消响应；它们未进入本次结论。HTML 是状态交互演示，实际后端证据来自 Python 脚本。
