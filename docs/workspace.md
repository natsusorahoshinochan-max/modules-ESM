# 项目、画布与保存

本文件说明项目工作区的有效要求、现有持久化约定和实现差距。需求依据是[当前有效决策](documentation-governance-decisions.md)，未解决事项见[治理问题清单](2026-10-15-documentation-governance-issues.md)。文中的“要求”不代表功能已经交付。

运行范围、失败与批内续算见[执行规范](execution.md)；数据导入、结果复用与导出见[结果规范](results.md)；专用编辑行为见[Prompt 编辑](prompt-editing.md)。

## 手动保存与未保存编辑

用户手动保存项目；流程、参数、Prompt 等内容与同次编辑的画布布局一起保存成功，才算保存成功。允许保存未完成的流程，保存不要求先完成运行编译。只有满足运行条件的 Workflow Commit 才能执行。

有未保存修改而离开时，提醒用户选择放弃修改离开，或取消并继续编辑；不提供“保存后退出”。需要保留修改时，先取消离开，再手动保存。点击运行时，如存在未保存修改，仍要求用户明确选择“保存并运行”；保存成功后启动，取消或保存失败都不启动。打开其他项目、命名版本或页面导航不能暗中代替用户保存。

编辑器的“确认操作”和项目持久保存分别处理。结构变换确认、单格输入确认或接受模块编辑内容，表示采用该次编辑；它们本身不能成为自动保存项目的理由。撤销与重做恢复已采用的编辑内容，不重新产生随机结果，也不删除既有运行结果。

同一项目计算运行期间禁止修改该项目，结束或取消后恢复编辑；仍允许查看流程和结果。具体编辑控件的覆盖仍须按此要求核对，不能只禁用“运行”按钮就认为已经实现运行锁。

## 未保存提醒的边界

| 场景 | 当前路径与数据影响 |
|---|---|
| 应用内打开项目、查看命名版本、新建项目、返回已保存工作 | [App](../webui/src/App.tsx) 的 `askUnsaved('leave')` 先完成输入编辑，再提醒放弃或取消。放弃只丢弃内存修改；取消继续编辑，需要保留时由用户手动保存。这里的离开指已有工作区切换操作，不新增退出流程。 |
| 浏览器刷新、关闭标签页或窗口 | 未保存时请求 `beforeunload` 原生离开／取消提醒，不调用保存。确认离开会失去未保存编辑；取消后可手动保存。 |
| 关闭前端时已有后端 Run | 后端继续执行，未保存提醒不发送取消计算指令。 |

[HTML 标准](https://html.spec.whatwg.org/multipage/browsing-the-web.html#steps-to-fire-beforeunload)规定原生提醒由浏览器控制，依赖用户激活等条件，只决定是否允许卸载。[Chrome 页面生命周期说明](https://developer.chrome.com/docs/web-platform/page-lifecycle-api#the-beforeunload-event)指出关闭事件可能不触发，尤其后台终止；因此不能保证任何关闭方式都会弹框。当前要求使用原生提醒，不增加桌面宿主或通过后台保存规避禁止自动保存的要求。

## 持久化接口与保存失败

当前后端由 `WorkflowAuthoringService` 发布不可变 Draft/UI revisions，并以一条 workspace record 绑定精确版本。`PUT /projects/{project_id}/workspace` 接受 `workflow`、`ui_state` 或两者；省略的部分沿用已有版本。`GET /workspace` 返回当前 Draft、精确 UI state 和 workspace revision。UI-only 保存不创建新的科学 Draft。

Draft/UI 内容先追加，最终 workspace record 发布后成为当前工作。中断留下的未引用内容不成为当前工作；已有记录不覆盖，revision 分配也不重用已占用编号。UI state 是后端不解释内容的 JSON 对象，当前前端用 `canvas` 保存画布状态、用 `binding_parameter_memory` 保存暂未激活的 Binding 配置。

手动保存携带 `expected_workspace_revision` 与 `expected_draft_revision`，持久化边界在写入前与当前 head 比较一次。冲突保持用户编辑，不自动合并或重试。读取、发布与存储各自信任已由所属边界接纳的事实，不增加重复校验。

`WorkspaceEditor` 区分用户期望内容与后端已确认内容，协调完整编辑、撤销、保存失败和明确重试。失败时保留待保存内容；依赖持久化成功的动作不能继续。发布前失败不改变当前 head；发布后元数据或响应失败不意味着发布被撤回。明确重试可读取当前回执以确认结果，不能把未确认写入展示为成功，也不能悄悄合并另一个内容基线。

这些是现有保存机制的有效边界，不授权每次编辑自动发送保存。手动触发时机仍按上节要求。

## 命名版本与返回工作

命名版本保存当前精确 Draft/UI 对，不要求编译，名称可以重复，以版本 ID 区分。查看旧版本只读；旧版本及打开前的已保存工作均应保持可返回。

编辑旧版本时，先在内存保留用户修改，到用户手动保存时再发布新的当前工作，保留版本来源与打开时的返回点。同次保存使用一个完整 Draft/UI 发布结果，不能先覆盖原工作再单独 fork。长编辑会话的预览基线来自正在查看的版本；布局变更应用于最新待编辑 UI，不能以旧会话的整份布局覆盖后来的布局操作。

当前后端 `:fork` 和 `workspace:return` 分别提供版本派生与返回已保存工作；客户端在内存中编辑，显式保存时才触发版本派生发布。

## 项目生命周期、复制与输入

项目身份在重命名、移入最近删除、恢复和服务重启后保持稳定。当前最近删除状态由 `deleted_at` 表示，普通项目列表排除已删除项目，恢复清除此状态。移入最近删除只更新元数据，用户明确永久删除后才清理对应存储。

当前完整删除操作由 Run Runtime 持有项目 idle lease：存在 reserved 或未终结 Run 时返回 `project_has_active_runs`，不自动取消。用户可以等待完成，或明确取消后再执行删除。永久删除只接受已移入最近删除且未受保护的项目，清理 Project、output、cache 和 Run scopes，再清理运行注册及 Commit 缓存。跨文件系统删除不是事务；存储失败立即返回失败并停止后续步骤，已删除内容不自动回滚。

复制项目包含流程、参数、所需输入和布局，副本从未运行状态开始，不整体复制运行记录、结果、缓存、命名版本或来源历史。明确采用为输入的历史结果属于“所需输入”，不因它曾经是另一次运行的输出而丢失。已采用输入必须独立可用；删除来源项目不能使采用方失效，也不能要求用户维护内部引用。采用时将所选值及所需依赖保存为目标项目的不可变 Project Input。

现有普通 `:duplicate` 按 Catalog 声明的 Project Input 参数复制所需输入并改写项目作用域，`copied_from_project_id` 只是来源说明。它不复制运行输出和历史；已明确采用的历史结果作为独立 Project Input 随流程复制。

已上传的不可变 Project Input 与流程编辑是不同对象。取消导入或合并不修改流程，已上传输入仍列在项目中供复用，不做隐式垃圾回收。项目永久删除可清理其输入，但须满足已经采用到其他项目的输入继续可用的要求。

## 教学实例与默认入口

要求默认打开教学实例，保护原件并允许用户尝试编辑；首次手动保存才创建用户项目。首次编辑先保留在内存，不能立即持久复制。保存后的项目从项目列表重新打开；未保存退出使用同样的放弃、取消提醒。副本遵守项目复制范围，不自动继承教学运行与结果。

当前应用启动后通过公共协议发现 `webui-3gb1-example`、其 Workflow Draft 与随包分发的已完成运行。浏览这些现有结果不调用 Provider；新运行使用已配置的真实 Provider。受保护示例不能通过普通项目 API 重命名或删除。教学编辑与新增输入保留在当前浏览器会话中；首次手动保存通过 copy 请求一次提交流程、布局与输入，随后切换到没有运行记录或结果引用的个人项目。新增输入的检查与 Prompt 预览使用请求内数据，不创建临时项目或修改教学原件。

默认附带并启用官方功能模块。生产启动读取数据目录的 `modules.json` 包清单；没有清单时使用默认包，有空清单时建立空 Catalog。教学资源仅在文件与所需 Node Type/Binding 都存在时安装；首次安装编译当前教学流程，实际编译错误立即报告。已有教学 Draft、Commit 与 Run 保持原样，模块或随包流程更新不在启动时重新编译或替换历史 Commit；读取记录的错误仍直接报告。用户保存教学副本后，新运行按当前模块声明编译，不把历史教学结果视为当前模块的计算结果。没有教学项目时，前端打开已有个人项目；没有个人项目时显示创建、打开项目入口。新建项目使用同一画布与显式保存路径。空载体与已有项目均有“模块管理”入口，可选择外部 wheel 安装、启停、卸载模块及重新安装随附模块。变更前处理未保存修改，活动 Run 期间拒绝变更；成功后重新加载当前项目，缺失节点保留配置，恢复模块后可继续执行。卸载只移除模块包，不删除项目、输入或运行结果。应用内模块设置的当前差距见[Provider 配置](provider-configuration.md)。

## 画布与参数交互

- 搜索打开时聚焦输入框，方向键定位，Enter 添加，Escape 关闭。空白右键确定新增位置；从输出端口拖到空白时只展示兼容节点，新增节点与连线成为一次编辑。
- 连线按来源节点/端口及目标节点/端口识别。重连到单值输入时一致替换已有连接；有序多值输入保留同输入内原位置，跨输入移动则追加。无变化和重复连接是无操作，取消重连保留原边。批量删除整体接纳，保留必要的 Selection 引用清理。
- 折叠节点保留独立端口标记，但展开后才能创建或重连该节点的连接。端口解释精确类型、含义、必需性、多重性和输入顺序。兼容高亮只解释端口关系，运行可行性由后端负责。
- 多选支持组合、复制、删除。组可命名、嵌套、独立复制和解组；解组只提升直接成员。片段复制重建内部节点和 Selector/Objective 引用，外部连接待用户明确接入。
- Tab 进入组，组内 Tab／Ctrl+Tab 或面包屑返回；输入框中的 Tab 保持字段导航。每层保留自己的视图，层间导航不进入内容撤销历史。组布局不能覆盖不可见成员。
- 参数按公开 Node/Binding 合同展示，分组展开，Enter 接受，Escape 恢复。模型或 Binding 切换按已声明作用域保留参数，不因字段同名猜测其含义。用户使用枚举、数值及领域控件表达需求，不维护内部身份标识。

链与残基参数的选项来自该参数实际连接的来源节点和端口，通过输入检查或临时预览取得，不拼接无关输入的残基轴。使用已发布的残基轴时，须确认它与当前流程一致。临时预览不写入流程；缺少可用来源时明确提示，不悄悄替换或清除已保存参数。当前来源找不到的已保存值仍保留，并允许用户明确移除。现有来源解析与参数交互见 [parameter-choices](../webui/src/parameter-choices.ts) 和 [WorkflowParameters](../webui/src/WorkflowParameters.tsx)。

当前 React Flow 负责画布事件、测量、拖动及选择；领域编辑保留完整意图，不能把无效原始文本转成猜测值。异步工作按编辑 session 隔离，包括 A→B→A；过期回执不能写入新 session。快捷键分别尊重画布、矩阵、文本、三维持续操作和弹窗上下文。Radix 弹窗与菜单关闭后恢复焦点至入口或仍可用的工作区。

### 默认示例的显示

现有示例按真实接线分成五个阶段组和普通导出节点：模板→Prompt、生成候选与初筛、首轮折叠与筛选、设计序列、末轮折叠与筛选、导出。具体分组与参数映射由[默认展示配置](../webui/src/default-example-canvas.ts)维护；这里只规定解释原则。

组接口对应真实内部节点和端口，保留跨阶段引用及来源。阶段卡片直接操作现有参数或打开所属编辑器，不存第二份值，也不建立统一 seed、工具或阈值。分组是画布组织，不能暗中改动执行依赖或数据含义。现有预设采用单行和初始 100% 缩放；适合视图由用户主动触发，进入与返回保留每层工作位置。预设不自动重排已有个人项目。

## 当前差距与核对入口

| 已确认要求 | 当前实现差距 | 核对入口 |
|---|---|---|
| 手动保存、未保存退出提醒、保存并运行 | 内存编辑由用户显式保存；切换工作区提供放弃或取消，浏览器关闭／刷新请求原生提醒，不提供保存后退出 | [WorkspaceEditor](../webui/src/workspace-editor.ts)、[App](../webui/src/App.tsx) |
| 同一项目运行期间禁改 | 前端编辑 owner 与后端修改边界限制修改，结果阅读仍可用 | [App](../webui/src/App.tsx) |
| 缺少模块仍能打开并保留项目 | 画布以缺失占位展示未知 Node Type/Binding，保留原始配置、连线与布局；手动保存个人项目不依赖运行编译。模块恢复后的完整用户管理链仍需验收；缺失模块教学副本首次保存的输入依赖发现尚待对齐 | [workflow-authoring](../webui/src/workflow-authoring.ts) |
| 首次手动保存教学副本 | 首次显式保存一次发布完整个人项目，不带教学运行；命名版本修改亦显式保存 | [WorkspaceEditor](../webui/src/workspace-editor.ts)、[authoring](../core/workflow/authoring.py) |
| 运行历史及历史/跨项目输入采用 | 运行历史可选择单个已保存 Run，刷新及重新打开项目恢复查看选择；浏览不保存流程。画布采用历史结果先持久保存独立输入，再暂存来源节点；手动保存后可重开，来源永久删除不影响使用 | [App](../webui/src/App.tsx)、[结果规范](results.md) |
| 官方/外部模块、React 专用界面、多个查看器及应用设置 | 固定装配和专用分派尚未形成完整模块接入路径 | [架构](architecture.md)、[Provider 配置](provider-configuration.md) |


复制项目按当前节点声明识别需要独立保存的 Project Inputs；模块缺失时使用该项目已保存 Commit 中的节点声明。目标项目保存所引用输入的独立字节，源项目删除不会使其失效。若不完整 Draft 的缺失节点从未留下可用声明，仍可打开和保存原项目，但复制会明确报告依赖声明不可用，须恢复模块后再复制；不会猜测参数或复制全部输入。
