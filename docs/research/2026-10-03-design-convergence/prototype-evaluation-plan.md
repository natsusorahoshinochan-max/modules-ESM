## 1. 需要回答的问题

实验 P1 比较两种主要编辑对象，并验证编辑、准备、执行和采用的版本关系。实验 P2 验证矩阵与结构联动、局部坐标预览，以及 renderer 选择。两者都应产生可保留或推翻设计的证据。

原型是可丢弃的设计工具；不接入现有产品作为第二套生产路径。每个实验先写清假设、固定样例和判定条件，再实现最小范围。实验涉及科学计算的部分，必须先写明[科学问题表](interaction-and-interface-contracts.md)中对应的含义。

## 2. P1：来源编辑 → 准备 → 采用 → 撤销

### 假设与两种界面

假设 H1：A 的阶段视图能在不损害批量分析的情况下，使精细设计足够直接。假设 H2：同一编辑历史与明确版本能让用户理解运行期间继续编辑、采用和撤销。

制作 A/B 两个可点击的低保真界面，使用相同数据、术语、屏幕尺寸和任务脚本：A 打开研究阶段与专用编辑器；B 打开 Design Document 和具名 Workflow 绑定。不要让其中一个有真实反馈，另一个只有静态页面。

计算结果使用标注为演示数据的固定 fixture。它用于评估状态和操作，不宣称模型真实性、Provider 接纳或科学性能。真实模型无需参与第一轮界面比较。

### 固定任务

| 任务 | 操作脚本 | 必须可观察的结果 |
|---|---|---|
| P1-1 片段与目标 | 选择来源 A 的明确残基集合，映射到目标，改变一条轨道并预览 | 来源/目标身份与变化可读；科学未定义项不能由索引猜测 |
| P1-2 提交期间继续编辑 | 用 v1 准备 p1，编辑为 v2，尝试运行 | 界面说明执行 v1 或重新准备 v2；回执和结果关联正确 |
| P1-3 部分成功 | 展示一个尚未全部成功的 Run 中已发布结果 | 可看真实已发布对象；整体失败不隐藏可用结果，临时数据不冒充结果 |
| P1-4 采用并撤销 | 采用一个结果的指定轨道到 v2，得到 v3，再撤销和重做 | 来源引用与内容一起更新；不删除 Run；重新准备得到与当前内容一致的请求 |
| P1-5 晚到响应 | 让两次预览反向到达；旧保存未返回时继续编辑，再接收旧回执 | 预览不倒退；串行保存只确认对应版本，仍有新改动时不能显示全部已保存 |
| P1-6 启动回执丢失 | 接纳后隐藏响应，销毁并重建前端会话 | 从发送前的持久记录恢复同一意图，再查接纳事实；不因为重开而多启动一次 |
| P1-7 重复试验 | 用户明确选择同一输入再运行一次 | 新 Run 与旧 Run 分开；新启动身份不混同重复网络请求；随机条件明确 |
| P1-8 无 Prompt 研究 | 导入多条 FASTA，评分/折叠/比较，打开中间输出 | 两套方案都能完成；不能要求创建无意义的 Prompt |
| P1-9 多方法与跨 Run 比较 | 同一精确输入建立两种 Method/流程分支；修改拓扑并检查 B 的绑定适用性；查看中间输出并跨 Run 比较 | 能解释文档版本、Method、Metric、参考上下文与失效绑定；不可比读数不被隐式混排 |

提交与取消的真实持久语义在后续核心集成阶段验证。此原型中的事件脚本只能说明 UI 如何响应预定事实，不能证明本项目后端已经实现这些事实。

### 比较记录

先由设计者按脚本走查功能完整性，再邀请用户分别操作 A/B；保留顺序信息，避免第二次更熟练被误认为方案更好。若本轮只有用户一人，结果只用于该产品的直接反馈，不声称统计意义。

每个任务记录：是否独立完成、停顿或误解点、用户对输入版本和采用后果的解释、主动操作次数、往返切换次数、出错后能否恢复。操作次数是辅助证据，不能覆盖科学含义理解错误。

**保留 A 的条件：** J2/J3 路径清楚，J1/J4 不需要反复绕回图界面，用户能解释当前编辑与 Run 的版本关系。**转向 B 的条件：** 精细设计明显更直接，而且纯分析、多方法比较与中间输出没有新增人为步骤。若两者都混淆版本，先修共有的状态模型，不归因于界面形态。

## 3. P2：矩阵、双结构视图与局部坐标预览

### 假设与比较范围

假设 H3：固定、类型明确的 View Context 足以支持首轮多视图需求。假设 H4：局部坐标更新可消除当前连续操作依赖完整后端预览的问题；是否替换 renderer 需要同场测量。

对 3Dmol 与 Mol* 使用同一结构数据、残基身份、变换定义、相机条件和测试硬件。先实现各自最小可用更新路径，再比较结果；不能只比较一种优化实现和另一种故意全量重载的路径。

两种 renderer 共同的拟议 Interface 只是实验起点。记录每一种实现需要额外暴露的参数、事件和生命周期；若共用 Interface 变得过宽，应调整 Seam，不能强行以条件分支伪装可替换。

### 固定样例与任务

| 样例/任务 | 需覆盖的问题 |
|---|---|
| 单链、较小结构 | 基本拾取、矩阵对应、移动/旋转、确认/取消 |
| 多链、重复残基编号、插入码与缺失坐标 | 身份翻译；不能用 `chain/resi` 的偶然唯一性掩盖映射问题 |
| 同一候选的不同显示表示 | 改样式或重新载入后选区与镜头的寿命 |
| 两个候选，先无对应，再载入明确对应 | 独立操作与显式联动；不完整对应的可见反馈 |
| 相同几何经刚体变换得到不同原点/朝向 | 同步相对视角操作不冒充结构配准；镜头与显示变换不改科学坐标 |
| 小、中、大三个实际数据规模 | 更新路径随残基/原子数量变化的成本；报告确切规模 |
| 反复进入退出、切换结构、释放视图 | 旧响应写回、资源增长和相机意外重置 |

操作顺序固定为：矩阵选区 → 3D 高亮 → 3D 追加选区 → 数值移动/旋转 → 取消 → 再操作并确认 → 撤销 → 切换候选 → 重新打开。再分别开启镜头与选区联动，检查它们互不隐式开启。

另外延迟确认响应，分别在等待期间取消、编辑目标和切换结构，再送达原来的成功响应。它不能发布过期编辑；只有仍匹配目标 revision 与预览代次的成功结果，才替换临时画面并进入一次文档历史。

### 测量与判定

记录输入到可见反馈的 p50/p95、变换计算与渲染各自耗时、全量/局部更新次数、模型数量、资源释放后的内存趋势、首次装载和重复进入成本。截图记录身份与状态，录屏记录连续操作；不只报告平均帧率。

可将代表性桌面/中等结构下 p95 输入反馈不超过 50 ms 作为**待校准的交互目标**。它不是已测结论，也不适用于未说明的数据规模。固定硬件与样例后再确认目标，不能测完后悄悄降低标准。

以下错误无论速度多快都不能通过：选错残基、跨候选错误对应、确认后坐标含义改变、取消不恢复、旧响应覆盖新结构、镜头操作改变科学坐标。

若现有 renderer 在实际样例中满足交互与身份要求，保留它并重整 Structure Interaction 即可。若 Mol* 在这些要求、生命周期或必要展示能力上有明确优势，且其接入成本可接受，再选择替换。结果不明确时记录缺失证据，不宣布胜出者。

## 4. 下一轮的实际交付物

| 交付物 | 内容 | 完成标准 |
|---|---|---|
| 原型目录与说明 | 独立实验入口、假设、样例、依赖版本和运行方式 | 不混入产品发布路径；演示结果显著标记 |
| P1 A/B 交互原型 | 同一任务、同一状态数据，含错误/等待/恢复状态 | 九个任务均可走通或记录明确失败 |
| P2 渲染实验 | 两种实际 Adapter、相同身份与变换操作 | 可重复测量；声明尚未支持的能力 |
| 评估记录 | 固定源码快照、环境、数据规模、过程与结果 | 结论能追溯到证据，区分自动验证和人工判断 |
| 决策修订 | 保留/推翻哪些推荐，原因是什么 | 更新目标设计；必要时再写领域词汇和 ADR |

P1 的低保真交互比较可以先开展。P2 的性能结论需要真实 renderer 和浏览器；核心接纳、重启和真实 Provider 能力需要对应集成验证，不能由原型事件模拟替代。

## 5. 执行规则与结束条件

所有可运行代码、测试、类型检查、构建、浏览器和 Provider 检查在远端固定源码快照上执行，依照[后端验证政策](../../backend-verification.md#execution-policy)与 [WebUI 入口](../../../webui/README.md)。每批收集结果再修复；真实 Provider 验证需满足其前置门槛。纯文档评审与源码阅读不需要启动运行环境。

设计收敛可以在以下条件下进入正式实施：主编辑对象及反例有结论；编辑/保存/准备/Run 的身份和归属清楚；视图与研究选择的含义区分明确；科学操作的未定问题已针对首个实现用例解决；renderer 决定有相应证据或明确保留现状。

没有必要等待所有未来能力都设计完成。先完成一条完整旅程，再扩展到下一条；但不以多写一层通用框架代替尚未作出的产品和科学决定。
