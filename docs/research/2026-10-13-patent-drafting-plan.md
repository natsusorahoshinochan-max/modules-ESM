# 当前蛋白质设计软件的中国发明专利撰写分析

项目要求以[当前有效决策](../documentation-governance-decisions.md)为准；项目实现边界见[技术事实](2026-10-13-patent-project-evidence.md)。文中外部文献事实限定于所列检索日期，文档治理未重新核查法律状态或网页变化。

日期：2026-10-13。申请方向：中国大陆发明专利。

本文件分析如何把当前软件整理成技术交底和申请文件。它是写作方案及权利要求工作骨架，不是可直接提交的完整专利书，也不作可授权结论。依据是[项目实施证据](2026-10-13-patent-project-evidence.md)、[类似软件专利继续检索](2026-10-13-patent-similar-software-followup.md)、[当前领域定义](../../GLOSSARY.md)和已核验的中国国家知识产权局规则。本文不提供当前版本已通过运行验证的结论。

研究范围：技术效果围绕平台本身的模块与节点扩展、用户编排、数据传递、工作流执行及结果管理。具体计算模型的能力由用户选择的模块决定。本方案的效果论证和实施例应验证框架能否接入、组织并执行这些模块；无需以某个模型的预测表现或生物实验表现作为平台发明的中心。

写作范围区分两层：现有源码的注册、编译和执行机制可作实施事实；已确认的用户插件安装、React 专用界面、多个查看器和应用内模块设置仍需相应实现与材料。下列权利要求骨架只是专利研究假设，不是批准的产品设计，不要求保留旧目录、接口或扩建证据体系。ProteinMPNN 旧接入已决定重做，不能作为未来必须兼容的实施基线。

## 一、发明对象与推荐写法

研究名称：**《一种支持自定义模块与节点编排的蛋白质设计系统及方法》**。该名称为25字。较短的备选为《一种可扩展的蛋白质设计工作流系统及方法》。名称用于准确指明方案，不承担创新性论证；名称通常不超过25字、必要时不超过60字的规则见[CNIPA官方解读](https://www.cnipa.gov.cn/art/2024/1/18/art_2199_189880.html)。

**一个总发明构思：** 模块开发者将蛋白质研究工具、算法或计算服务封装成具有明确输入输出合同的功能模块和节点，项目用户安装启用后选择节点、执行方式和参数并连接端口，框架把用户图解析为确定的蛋白质设计执行关系，执行各操作并保存可解释的结果及来源。

专利的对象始终是这套整体软件。ESM、SimpleFold、ProteinMPNN是可接入工具的实施例；端口科学合同、编译、候选关联和执行证据是让整套软件实际工作的机制。它们不能取代整体发明对象，但与已有平台的区别若成立，须体现在有关权利要求的具体技术特征中。[实施细则第23条](https://www.cnipa.gov.cn/art/2023/12/21/art_98_189197.html)要求独立权利要求从整体反映技术方案及必要技术特征；[现行审查指南修改决定](https://www.cnipa.gov.cn/art/2025/11/14/art_99_202568.html)要求对权利要求限定的整体方案评价创造性。

不能只写“允许自定义模块、允许拖拽节点、能够执行蛋白质设计”三个功能愿望。应写清**模块声明如何成为节点合同、节点合同如何约束连接、连接如何确定执行及数据传递、执行如何产生并关联蛋白质结果**。整体范围与具体机制可以同时保留。

## 二、技术问题—整体架构—技术效果

### 1. 技术问题的落点

建议描述为：不同蛋白质计算工具的执行接口、模型或算法身份、科学数据表示和结果来源不同；模块开发者接入工具、项目用户自行连图时，需要使节点能够执行、端口之间的数据具有确定科学含义，并使多阶段结果能够与其实际方法、输入和来源对应。

这比“现有软件不够灵活”“用户需要更多模型”更具体。背景中不能断言已有技术没有模块扩展或可视工作流，检索已找到相关先例。也不能把困难描述成通用商业流程管理、账号权限或多租户调度问题，它们不是本项目当前技术问题。[项目证据](2026-10-13-patent-project-evidence.md#整体对象与角色)、[GLOSSARY.md](../../GLOSSARY.md)

### 3. 可以写的技术效果及证据范围

- **扩展接入：** 模块开发者按合同定义模块和节点后，注册描述把计算实现接入共同节点目录、图编译和执行框架，新增能力可与既有节点共同使用。
- **自主编排：** 同一批模块可以由用户设置不同参数、执行绑定和连接关系，构建符合其研究目的的多个蛋白质设计工作流，并保存这些定义。
- **确定的数据和执行关系：** 名义端口、输入数量、必需输入、Binding归属和图依赖被解析到执行计划；不兼容连接及有环图在执行前被拒绝，有序输入关系被保留。
- **异构工具协作：** Node Type的科学操作与具体执行方式分离，直接实现或Adapter通过明确的输入输出合同参与同一流程；用户所选Method和Binding可以被确定和记录。
- **结果关联与管理：** 对使用候选、结构评价或选择的流程，跨节点结果通过精确内容关联匹配；科学快照及执行证据对应所运行定义、结果来源、实际调用和复用，支持结果阅读及明确范围的再次运行。

效果证据应包括模块接入、不同工作流、连接与执行、节点间数据传递及结果保存的实际材料。现有固定装配不是已完成用户插件安装的证据。[项目证据及缺证](2026-10-13-patent-project-evidence.md#可使用的实例与缺证)

| 章节 | 应写内容 | 措辞样例 |

| 技术领域 | 蛋白质计算设计、科学软件扩展、图式计算工作流；与具体模型训练区别开 | “本发明涉及蛋白质计算设计及科学计算软件技术领域，尤其涉及一种通过自定义模块提供科学节点、并由用户连接所述节点构建和执行蛋白质设计工作流的系统及方法。” |
| 背景技术 | 如实介绍已有组件库、工具封装、图式科研流程；引用最相关文献，再指出接入、科学连接与结果关联需要解决的具体问题 | “已有科研软件支持工具组件化及图式流程执行。在整合具有不同科学数据合同和执行方式的蛋白质计算工具时，需要明确各节点的科学操作、所选方法、端口数据含义及跨节点结果来源。” |

| 附图说明 | 对各图说明其表达的机制、流程或实施例，不把界面截图当成机制的全部公开 | “图1为系统整体架构图；图2为模块定义及启动接入流程图；图3为工作流编辑、编译及发布关系图。” |

具体实施方式至少要使本领域技术人员能够实现下列关系：注册描述中的字段和引用关系；Node Type、Method及Binding的分工；端口类型、数量和规范表示；节点实例和连接记录；编译计划的解析内容；Commit保存内容和重编译关系；direct/Adapter两条执行方式；典型输入输出及来源信息；结果发布与用户取得结果的路径。

采用模型的实施例应交代模型收到什么科学数据、输出什么以及后继节点怎样使用这些输出，不需要虚构本项目对上游模型的训练发明。[CNIPA软件主题解读](https://www.cnipa.gov.cn/art/2024/1/18/art_2199_189877.html)、[现行指南修改决定](https://www.cnipa.gov.cn/art/2025/11/14/art_99_202568.html)

首次提交就应公开拟主张机制和合理变体。充分公开和权利要求支持受《专利法》第26条约束，后续修改受第33条原记载范围约束，不能把概念稿作为以后补入关键机制的占位申请。[专利法](https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html)

## 四、权利要求的工作骨架

### 1. 使用边界

下面把当前方案写成有因果关系的系统及方法骨架，用于确定保护结构和继续比较现有技术。**尚未确定足以区别现有技术、并对整体贡献必要的特征组合，因此它们不是可提交的最终权利要求。** 宽泛层只有产品功能，容易落入已知架构；全部实现细节一并压进独权又会过度限定。应完成逐项比较后决定独权保留哪些必要机制、哪些进入从属权项。

### 2. 独立系统权利要求候选骨架

一种支持自定义模块与节点编排的蛋白质设计系统，包括处理器和存储器，所述存储器存储由所述处理器执行的指令，其特征在于，所述指令使所述系统：

接收自定义模块的注册描述，所述注册描述提供至少一个科学节点类型及其输入输出端口的名义科学合同，并提供将该节点类型与确定的科学方法及直接执行实现或适配器关联的执行绑定；在应用启动时对所述注册描述的标识、引用和科学关系进行准入，形成不可变注册目录，并基于同一注册目录向工作流编辑端提供所述节点类型；

响应用户对节点类型、执行绑定、参数和端口连接的设置，构建节点实例组成的蛋白质设计工作流草稿；依据所述注册目录解析所述节点实例和端口连接，对端口合同、输入数量、必需输入及图依赖进行检查，将所述草稿编译为固定执行实现、数据编解码器、参数和科学数据关系的执行计划，并从所述执行计划提取该工作流使用的科学定义快照，发布不可变的可运行工作流；

依据经准入的所述工作流及其执行计划，按所述图依赖执行节点，利用所选执行绑定的直接实现或适配器产生符合所述端口科学合同的输出，将所述输出提供给连接的后继节点并发布工作流结果，保存与所述输出相适应的候选身份、谱系和来源，以及与所述运行相对应的执行证据。

上述骨架的整体关系是：**注册描述确定编辑和编译共同使用的科学合同；用户连接形成待解析图；编译把图转成确定执行关系并固定解释结果所需定义；执行按照该关系产生和传递科学输出；结果与实际科学操作及来源对应。** 不是把六项软件功能并列后就认为构成可授权方案。运行时按当前Catalog重编译及科学身份比较，可以在必要时并入独权，也可以在从属权项展开。[项目证据](2026-10-13-patent-project-evidence.md)、[运行说明](../execution.md)

### 3. 对应独立方法步骤

1. 接收自定义模块注册描述，建立科学节点类型、名义端口合同、Method和Execution Binding之间的关联。
2. 在启动时完成注册准入，构建不可变注册目录及其编辑能力投影，使注册节点可被工作流编辑端选择。
3. 根据用户输入创建节点实例、选择执行绑定、配置参数并连接端口，得到蛋白质设计工作流草稿。
4. 依据所述目录解析和检查草稿，生成完全解析的执行计划；从该计划提取实际使用的最小科学定义快照并发布Workflow Commit。
5. 响应运行请求，以当前注册目录重编译并准入所述Commit，按图依赖执行直接实现或适配器，并按端口合同向后继节点传递科学输出。
6. 发布工作流结果并保存适用于输出的候选身份、谱系和来源及运行证据，向用户提供其自定义工作流产生的蛋白质设计结果。

系统和方法应描述同一技术实现，之后可准备相应的计算机可读存储介质和计算机程序产品主题；改变保护主题不能解决已有公开造成的新颖性问题。[CNIPA官方解读](https://www.cnipa.gov.cn/art/2024/1/18/art_2199_189877.html)

### 4. 八组从属限定思路

| 组别 | 可进一步限定的当前机制 | 如何支撑整体系统 |
| --- | --- | --- |
| A 模块及执行绑定 | 每个Node Type拥有一个公共Node Definition；一个Node Type具有一个或多个Binding；每个Binding固定一个Method并关联direct实现或所需Adapter；环境配置与科学参数分离 | 用户扩展模块和选择执行方式的合同 |
| B 端口及连线 | 名义Port Type规定科学准入、规范表示与内容身份；编译检查数量、必需输入、Binding归属、无环性及有序many输入 | 用户连接的图能够确定地变成数据与执行关系 |
| C 科学快照及再准入 | 从同一Plan提取最小定义快照；当前Catalog重编译后比较实际使用的科学身份；不一致时拒绝执行旧Commit | 模块变化后仍明确工作流及结果的解释依据 |
| D 适配器转换 | Adapter明确翻译Provider输入、输出、错误与provenance，保持Node Type的科学操作含义；直接实现无需强制配置Adapter | 不同科研工具在共同框架中执行的方式 |
| E 跨节点结果关联 | Candidate reference包含identity、nominal datatype和canonical content digest；关系不靠集合下标推断；需要时分别记录Prediction Axis和Resolved Structure Axis | 设计、折叠、结构评价节点之间的精确结果关联 |
| F 评价及选择 | Metric、Method和Observation Context分别声明；观察精确绑定候选；需要排名时按兼容的显式Utility Transform转换后组合 | 用户构建含评价、筛选和多目标偏好环节的设计工作流 |
| G 执行及耐久证据 | 区分节点尝试、真实操作和引擎调用；缓存命中先于Readiness且不虚构调用；节点输出与终态一次耐久发布，Selection结论与Run终态闭合 | 解释工作流实际执行、复用和结果发布的因果关系 |
| H 局部重执行 | 指定source Run；按当前Result Identity核对并复用已发布成果，执行指定范围，保留原producer Run来源 | 支持用户调整自建工作流并利用已有计算结果 |

上述组别可并列依附独权或按逻辑逐层依附，不能机械串成必须包含全部机制的一条长链。E、F只限定使用相关科学值或评价选择功能的实施方式，不能写成所有模块输出必含评分或残基轴。A—H都服务于整体软件，不要求另立残基算法、评分方法或某个模型发明。[GLOSSARY.md](../../GLOSSARY.md)、[结果与筛选说明](../results.md)、[模块能力说明](../module-capabilities.md)、[运行说明](../execution.md)

## 五、三个整体实施例与六张图

### 实施例一：模块如何成为用户可编排的节点

沿现有ESM3 package和folding package展示：Node Definition、Port、Method及Binding定义；Module Package Registration聚合；显式纳入应用装配入口；启动构建目录；编辑端提供节点；用户选择节点和Binding，连图、编译并运行。这是当前接入机制的实施证据，而不是模型算法的原创说明。

### 实施例二：完整3GB1蛋白质设计工作流
