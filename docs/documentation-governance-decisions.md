# Protein Workbench 文档治理：当前决策

本文件记录用户确认的当前有效要求与范围边界，是文档治理的需求依据。已确认要求不代表现有实现已经满足；具体变更按当前任务授权执行。

问题与证据见[文档治理问题清单](2026-10-15-documentation-governance-issues.md)。问题清单中的未核实事项不自动成为本文件的要求。

## 文档治理（Q1）

旧设计、旧验收记录应从当前仓库移除，不保留独立历史档案。整理时须识别其中仍有效的功能要求，避免一并丢失。

该删除范围不包含用户项目、科学运行结果或原始实验数据。

## 载体与模块（Q7）

### 角色与职责

产品决策者同时承担开发工作；“项目用户”专指未来使用本软件的人。产品行为、开发契约和必要的实现取舍均可与决策者讨论，不能以“属于开发者职责”为由排除这些讨论，也不能因此要求未来项目用户承担模块内部实现与正确性维护。

- **项目用户**负责安装、启用和使用模块，不承担模块内部实现的设计、审查或技术选择。
- **项目开发者**负责软件项目的产品行为、模块开发规范、共享约定及载体的公共接入、管理、编排、运行、保存和数据传递能力；不是指创建某个蛋白项目的使用者。
- **模块开发者**负责模块内部的数据处理、模型或算法调用等实现，并遵守项目的模块开发规范。
- **载体**提供模块安装与管理、流程编排、运行、保存和数据传递等能力；前端画布是其用户界面的一部分。
- **模块**提供具体功能。模型、算法或外部服务只是模块内部可能使用的工具，模块不等于模型。

载体不额外施加针对具体模型、算法或内部处理方式的使用限制。开发规范约束模块开发者，不把开发责任转交给终端用户。同一个人可以兼任项目用户、项目开发者和模块开发者，三种身份的责任仍分别归属。缺少公共接入能力由项目开发者补足，不要求模块开发者修改载体私有实现来接入。

### 官方与外部模块（Q7.3）

官方自带的具体功能与外部模块使用同一套接入规范，包括所需专用界面的接入。官方模块不使用外部模块无法使用的特殊接入路径。

统一接入规范不要求各模块复制共用代码。共享设施的组织方式与代码归属尚未确定，不能依据现有目录结构认定最终边界。

### 载体独立使用（Q7.4）

没有启用任何具体功能模块时，载体仍能正常启动，创建、打开和保存项目，显示画布，并安装、启用和管理模块。

蛋白质生成、结构预测、评分和 Prompt 编辑等具体能力由相应模块提供，不是载体启动与基本使用的前提。载体独立可用不意味着缺少模块的既有流程仍能正常计算。

## 插件管理（Q8）

支持用户选择插件包后安装并启用，以及启用、禁用、安装和卸载插件，符合所要求的 Blender 式操作方式。不能将该能力缩减为由开发者手动修改启动代码接入。

官方功能模块默认附带并启用（Q42），仍遵守与外部模块相同的接入规范。该决定不意味着自动下载全部模型或代填远程服务凭据。

## 前后端运行边界（Q17）

项目采用前后端分离架构，计算任务由后端执行。关闭前端不影响仍在运行的后端任务；前端退出不构成取消任务的指令。未保存编辑的退出提醒仍遵守 Q13，与后端任务生命周期分别处理。

该约定不涉及关闭后端进程、停机或后端故障时的处理。

## 远程调用（Q9）

远程模型调用失败后，沿用当前已有的默认尝试次数上限进行尝试。

已核对的 ESM3、ESMFold2 SDK 默认上限为总计 5 次尝试，并仅对指定错误重试。这是现有配置事实，不是所有模块、所有错误必须尝试五次的统一要求，也不是永久固定的上限决定。

重试实现属于开发者职责，不要求终端用户审查 SDK 内部处理。

## 已实现模块的功能要求

### 单条序列导入（Q19）

单条序列导入遇到含多条记录的 FASTA 文件时，提示用户改用批量导入，不自动将不同记录拼成一条序列。

### Prompt 编辑（Q20）

随机插入得到的残基应当能够像其他残基一样继续删除、插入和编辑。随机生成不构成限制后续编辑的理由；来源与编辑结果的正确记录由模块开发者负责。

随机编辑确认采用后固定实际得到的位置与结果。后续删除不重新抽取或补足原数量；已采用操作的 seed、数量和范围作为只读记录，再次随机处理基于当前内容发起新操作，经预览确认后采用。用户仍可直接编辑已有结果，并通过普通撤销恢复操作前状态，不通过修改或删除历史随机步骤重算后续编辑。

清除某个位置的坐标条件后，该位置此前采用的变换不再重放；以后重新设置坐标时按新值采用。其他位置保持原有结果，撤销清除恢复清除前的坐标。模块开发者维护操作含义、位置对应与已保存内容，载体提供通用编辑、撤销和手动保存机制，不要求项目用户清理内部引用。

## 功能模块设计

### 设计尺度

本项目讨论中的科学正确性，以正确传参为标准：将用户指定的数据、对象、位置和参数正确传入工具，并正确接回所需结果。必要的数据转换服务于正确调用，不额外构建指标、证据、验证或抽象体系，不以“科学性”为由增加未要求的产品功能和开发负担。

模块按用户要完成的任务划分，工具在模块内部复用，科学数据与区域含义保持一致。模块职责不等同于节点数量或代码目录；一个模块可以提供多个节点、专用编辑器和查看器，同一工具可以服务多个模块。

| 模块 | 当前确认的职责 | 职责边界 |
|---|---|---|
| 蛋白数据导入与导出 | 导入、导出序列、结构及相关结果，保留来源、链和残基身份。 | 不自动改变蛋白内容或推断不存在的指标。 |
| 序列与设计条件编辑 | 编辑序列、Prompt、固定区域、可变区域和结构条件。 | 表达设计内容与条件，不负责调用工具生成候选。 |
| 序列生成与设计 | 序列补全、受约束生成、骨架条件下的序列设计，以及工具支持的序列与结构联合生成。 | 联合生成的结构不能自动作为独立验证结果。 |
| 结构预测 | 对序列进行折叠，获得结构及本次预测附带的置信度。 | 新预测结构不能冒充对原有结构的评价。 |
| 结构编辑与处理 | 提取链或片段、进行明确的结构转换和坐标调整。 | 指定评价区域不等于裁剪、拼接或改写原结构。 |
| 结构比较 | 比较完整结构、链或不连续区域，完成自动对应、整体对齐及 TM-score 等比较指标计算。 | 不承担可溶性计算或候选筛选。 |
| 候选评价 | 对已有候选追加计算，如可溶性、序列与骨架适配指标、已有结构的独立置信度评价。 | 不接管其他模块自然产生的所有分数；是否进一步拆分独立功能模块仍待确定。 |
| 指标分析 | 对已有指标做区域统计等明确的分析操作。 | 不暗中重新运行预测工具。 |
| 候选筛选与排序 | 按阈值、多条件和排序规则选择候选。 | 使用已有评价结果，不负责补算分数或重新定义指标。 |

### 筛选规则与排序

每个筛选节点拥有自己的条件、指标选择和排序设置，复制节点时一并复制。不保留节点引用 Workflow 全局筛选规则的安排；载体不再专门解释或重映射筛选规则。已保存工作与历史结果仍须保全。

单指标排序和 top-k 直接使用指标原值及用户选择的升降序，不强制先转换为 Utility。多指标加权所需的单位、方向和尺度处理须明确，不由单指标排序规则隐含决定。

保留结果页临时筛选和排序的查看用途；缺少必需分数时明确停止本次筛选或排序，不通过隐藏候选或将缺值排到末尾继续。结果页与画布的筛选判断由同一功能实现负责；临时查看不因此成为持久计算或修改 Workflow。

评价选择须能区分实际方法、参考对象、区域等含义。选择后仍有歧义时明确停止，不擅自取第一条、最新值或平均值。用户选择研究所需评价，模块开发者维护准确匹配与可理解的选择信息，不要求用户维护内部 ID。

top-k 表示最多取 k 个；候选不足时返回全部，输入为空时返回空集合。分数相同时保持输入候选的相对顺序，不以内部 Candidate ID 决定顺序，也不因临界并列扩大 top-k 数量。候选数量不足与缺少必需分数分别处理。

提供多指标加权排序及独立 Pareto 选择。Pareto 按指标原值与所选优劣方向判断支配关系，不强制权重或效用转换；输出保持输入相对顺序，不视为综合排名。本轮目标功能移除当前含义不清的 diversity 操作，未来的指标表现、序列或结构多样性须分别明确，不自动新增。已保存配置与结果仍须保全。

用于加权的评分转换默认由指标提供模块负责，包括自然产生指标的生成、预测模块和独立评价模块；筛选模块按共同约定使用。共用实现可以复用，载体不制定公式。模块开发者提供可直接使用、含义与适用条件明确的转换，用户选择评分方式和权重，不默认要求用户设计公式或填写转换端点。原始指标保留；没有适用转换时仍可原值筛选、排序和 Pareto，但不由载体自动缩放后用于加权。数值同在单位区间不代表加权含义相同，现有转换公式不因已存在就获确认。

加权使用非负相对权重，以加权和除以权重总和。零权重项不参与计算，也不要求该项分数；总权重须大于零。负权重不允许，优劣方向由评分转换表达；参与计算的指标缺少必需分数仍停止。

这些要求的当前实现与使用入口见[结果与筛选](results.md#筛选排序与手动选择)；要求的确认与具体运行验证分别记录。

### 通过画布组合功能

模块提供可组合的功能，用户通过画布上的节点连接组织数据处理流程与作用范围。例如，整批候选取前十名、每个骨架对应的候选分别取前十名，都应能够通过用户构建的流程实现，不由产品预先固定为其中一种规则。

设计审查应检查模块能力及其组合是否足以表达这些流程，不把本应由项目用户构建的流程当成需要产品负责人逐项选择的固定行为。本原则不预定具体节点数量、分组表示或执行机制，也不改变载体与科学功能模块的职责划分。

### 工具与模块的关系

ESM-3、ESMFold2、SimpleFold、ProteinMPNN、SoluProt 等是模块使用的工具，不直接决定模块划分。ProteinMPNN 的设计与评价能力可以分别服务相应功能模块；SimpleFold 的预测与独立评价能力同样可以分工使用。共用工具适配与代码复用由开发者负责。

工具运行时自然产生的分数随结果保留，不因模块划分而丢弃后要求用户重新计算。不可拆分的联合生成能力可以保留为完整功能，不假装等同于独立的生成与验证操作。

### 共用科学约定

结构比较、结构处理和指标分析等模块共用一致的区域表达与选择交互，能够表达指定链上的不连续残基区域。模块间保持真实残基身份与编号对应，不要求用户管理内部映射。

指标保留其适用候选、结构、区域、比较对象及计算来源。已有分数、追加计算结果与统计结果不能丢失各自含义。这些是科学功能模块间的约定，不将蛋白质科学逻辑归入载体。

设计以局部比较、设计后的独立验证、跨工具预测比较、外部数据使用、追加评价和多目标筛选等场景检验职责覆盖。场景示例不自动确定所有具体操作、统计规则或参数；包结构、节点数量及内部实现仍由开发者设计。

### 评价关系与生成来源（Q24）

评价关系与生成来源必须分开，作为模块开发契约。生成来源如实记录候选实际由哪些输入和计算产生；评价关系记录本次评价所使用的候选与参考对象，可由用户构建的流程指定，不改写真实生成来源。

ProteinMPNN 评分强制要求输入结构是序列唯一原始父结构，属于已确认的实现缺陷，必须修正。应支持独立导入的序列与结构，以及已有序列与其他骨架的评价组合，前提是符合所调用工具的输入与参数要求。

模块负责正确对应所选对象和位置，结果明确保留本次评价对象及来源；不得为通过评分而伪造生成父子关系，也不得把解除谱系绑定解释为取消工具的输入要求。具体数据表示和实现方式由开发者设计。

### ProteinMPNN 功能重做

当前 ProteinMPNN 接入与新的功能模块设计存在大量冲突，后续应从头重做，不以逐项修补旧接口的方式完成。重做应依据当前模块职责和工具输入与参数要求重新定义功能及输入输出，不以旧节点、端口或谱系限制作为必须兼容的要求。

当前文档治理任务不执行代码替换。逐残基评价结果等尚未确认的具体功能范围，不能因决定重做就自动视为已批准。

重做以正确传参和所需功能为尺度，不额外建立科学契约或证据体系。

### 工具参数开放（Q26）

对于项目已决定提供的工具功能，官方支持、适用于该功能且影响计算结果的输入与参数，应允许项目用户明确配置。默认值须有明确依据，不施加没有依据的额外限制；开发者负责依据官方接口正确处理参数及其相互约束。

常用参数与较少使用的参数可以分层展示。文件路径、计算设备等部署配置另行处理。本原则不自动新增尚未决定提供的工具计算模式或功能。

### ESMC 结果输出（Q27）

ESMC 表征功能同时支持获取整条序列的 embedding 和实际逐位置 logits 数值，以可选输出提供，供项目用户查看或连接后续模块使用。不能只保留 logits 矩阵尺寸而丢弃所请求的实际数值；logits 不作为概率表述。

本决定不要求新增分析算法，也不扩展为保留所有工具内部数据；其他输出模式及具体模块归属未由此确定。

### 历史结果直接复用（Q28）

支持直接将历史运行中的结果选作后续计算输入，无需重新生成，也无需先导出再导入。后续流程由用户在画布上构建，不引入已决定删除的“保存为流程”功能。

### 跨运行结果查看范围（Q29）

不提供将不同次运行的候选放在一起并排查看的功能。仍支持分别打开历史运行及将其结果用于后续计算；本决定不取消结构比较等计算模块的功能。

### 结构导入格式（Q30）

结构导入同时支持 PDB 和 mmCIF。各工具所需输入格式由 Adapter 正确转换，不要求所有工具原生支持两种格式，也不由此决定新增其他格式或导出范围。

### 跨项目结果复用（Q31）

支持在一个项目中直接选用另一个项目的历史结果继续计算，无需先导出再导入。不增加跨运行并排查看功能；数据传递的内部实现由开发者负责。

### 项目复制范围（Q32）

复制项目仅包含流程、参数、所需输入和布局，不复制运行记录与结果。副本从尚未运行的状态开始。本决定不取消将历史结果明确采用为输入的能力；所需输入与历史运行记录、输出的整体复制是不同范围。

### 已采用输入的独立可用性（Q33）

一个项目已将另一个项目的结果采用为输入后，即使永久删除来源项目，采用方仍能正常使用该输入。数据保存与引用维护由开发者负责，不要求项目用户管理内部引用关系。

### 结构导出格式（Q34）

结构导出同时支持 PDB 和 mmCIF，由用户选择格式，包括结构导出功能及结果页的结构导出。各格式转换由实现负责，不要求用户另行使用外部软件转换。

### 多构象结构输入（Q35）

支持使用结构文件中的多个构象：用户可以选择其中一个，也可以将多个构象分别作为候选用于后续计算。相关模块提供选择和拆分能力，不要求用户在外部软件中预先拆文件。

### 非蛋白组分的结构操作（Q36）

结构中的配体、金属离子、水、核酸等组分，在查看、选取和导出时保留并支持选择。计算工具是否接收这些组分依其接口处理，不要求所有蛋白模型支持所有组分，也不自动增加对接等计算功能。

### 结果导出的参数说明（Q37）

导出结果时附带已记录的、产生这些结果所用的参数说明，使用户离开软件后仍能查看相应设置。不新增日志或证据体系，不补造未记录的信息。

用户结果导出统一下载 ZIP，内含所选格式的数据文件及已有计算参数说明，包括结果页的所选组分导出和导出节点的附件下载。组分导出注明来源结构与所选组分，不将原计算参数表述为针对片段重新计算的参数。模块负责数据格式与科学含义，载体提供同样可供外部模块使用的公共打包与下载能力；内部 Artifact 与后续计算的数据格式不因下载打包而改变。

### 未全部完成批次的成功结果（Q38）

一次生成或折叠请求多个结果，中途失败时，保留已经成功完成的结果，允许查看和导出，并明确显示本批未全部完成。不要求解析或修复失败工具的残缺输出。该决定不授权部分结果自动进入下游；节点失败后的依赖阻塞仍按 Q15。

### 结构文件导入数量（Q39）

不支持一次性导入多个结构文件，结构文件逐个导入。单文件内多个构象的选择及拆分仍按 Q35 支持，不将文件数量限制扩展为候选数量限制。

### 批内请求失败后的停止行为（Q40）

生成或折叠操作依次发起多个独立请求时，一个请求在用完已有适用重试后仍失败，则停止本批剩余尚未开始的请求。已成功结果按 Q38 保留供查看和导出；整批明确显示未全部完成，失败节点的下游按 Q15 阻塞。

该决定不增加重试次数，也不允许吞掉输入或程序错误后继续处理。

### 主动继续未完成请求（Q41）

支持用户在批次失败停止后主动继续未完成部分：在同一批输入和计算参数下，跳过已成功请求，仅重新尝试失败及尚未开始的请求。此操作不是自动重试，不改变 Q40 的当次失败停止行为，也不增加已有自动尝试上限。

输入或计算参数改变时按新计算处理。节点级重跑不能等同于批内续算。

### 默认模块状态与启动内容（Q42、Q43）

官方功能模块默认启用，用户仍可禁用、卸载和安装其他模块。默认打开教学实例，不采用项目首页或空白项目作为已决定的默认入口。

空载体独立可用的要求仍有效，不能把特定教学实例或科学模块作为载体启动的必要条件。

### 教学实例编辑与保存（Q44）

默认打开并保留原始教学实例，允许用户尝试编辑。首次手动保存时保存为用户自己的项目；未保存退出遵守放弃、取消提醒规则，教学原件不被修改。用户保存的项目可从项目列表重新打开。

编辑先保留在内存中，到用户明确保存时才创建持久化项目，不因首次编辑自动复制或写入。项目复制范围仍按 Q32，不自动复制运行记录及结果。

### 专用界面开发接口（Q45）

模块专用界面统一采用载体提供的 React 接口，官方与外部模块遵守相同的接入规范及明确的共享依赖版本约定。这是模块开发规范，不限制项目用户连接节点或使用计算功能的方式。接口见[模块 UI 契约](module-ui.md)。

### 同一数据的多个查看器（Q46）

允许多个模块为同一数据类型提供查看器。打开结果时使用默认查看器，用户可以切换展示方式；不能按模块加载顺序任意覆盖。切换只影响展示，不改变计算结果，也不新增跨运行并排查看功能。默认选择与切换见[模块 UI 契约](module-ui.md#结果读取与查看器)。

后端读取与前端加载均须支持外部模块，不能只支持前端分派；不要求外部模块将自定义数据伪装为内置蛋白类型。

### 模块运行配置入口（Q47）

提供应用内模块设置界面，允许填写远程服务凭据、指定后端可访问的已有模型位置，以及模块需要的服务地址、外部程序位置等配置。配置项由模块声明，载体负责展示、保存并提供给模块；模块负责按自身接口使用配置。

该决定不包含自动下载模型或自动安装计算环境。部署配置与温度、采样次数等节点计算参数分开，不要求项目用户修改环境变量或启动脚本才能完成这些配置。

## 尚需形成具体方案的开发事项

模块接入、共用数据和交互、插件依赖与版本、参数与结果表示等，需要依据当前决定形成具体设计。可以与产品设计者兼开发者讨论实际取舍，但这些事项本身不是需要重复确认的产品行为，也不授权增加抽象或检查体系。

保存、取消、运行与批次失败的行为按现有决定落实。局部采用的内部处理不额外规定尚未确认的默认保留或清空规则。没有改变远程重试范围、制定全平台重试策略或禁止外部插件提供类似“保存为流程”功能的新增要求。

## 未确认的额外功能范围

缺分数时由用户主动排除缺分候选后继续的额外操作尚未确认；当前要求仍是缺少必需分数默认停止对应筛选。其他未获明确确认的工具模式、输出和示例细节不自动成为开发要求。

当前决定之间未发现必然矛盾。尚需细化的设计不得自动补成新需求；现有代码或旧文档与这些决定不同，属于待对齐的实现或文档差异。
