# Protein Workbench WebUI 功能规格

- **状态**：功能基线与八个原型方向已确认；原型结论于 2026-08-31 完成收敛
- **目标用户**：不写代码的蛋白质研究人员
- **范围**：用户可见功能、交互和科学表达
- **不在本文范围**：前后端协议、技术栈、部署、持久化实现、代码结构和实施拆分

本文是当前 WebUI 功能讨论的权威记录。`CONTEXT.md` 仍然拥有项目领域词汇；特别是 Node Type、Node Instance、Workflow、Port、ProteinPrompt、Candidate、Metric Definition、Method 和 Run 的含义不由 UI 改写。

`docs/2026-08-18-frontend-rewrite-discussion-design.md` 只是一份较早的讨论稿，其中的工程建议不因本文而自动接受。后续工程讨论必须从本文已经确认的功能出发，不能反过来用现有代码或协议限制用户功能。

## 1. 产品入口与默认示例

### 1.1 启动行为

- 每次启动 WebUI 都打开一份干净的默认示例流程。
- 不显示教程、分步向导或引导遮罩；用户直接看到完整节点画布。
- 顶部提供“项目”菜单，用于搜索并打开以前保存的个人流程及其版本。
- 用户可以从顶部或画布入口新建空白流程。

### 1.2 默认示例流程

默认示例展示以下研究过程：

```text
PDB
→ 编辑 ProteinPrompt
→ ESM-3 生成
→ 评分
→ 筛选
```

- 默认示例本身保持不变。
- 用户第一次修改默认示例时，WebUI 自动创建个人副本，不弹出阻断操作的复制对话框。
- 后续修改发生在个人副本上。

### 1.3 首批覆盖的三个科研场景

首批产品不是只有节点编辑器，而是需要让不写代码的蛋白质研究人员完整完成以下三个场景。
这些场景是可编辑的示例流程和用户旅程，不是固定、不可更改的向导。

1. **批量序列评分、筛选、结构预测和导出**
   - 用户导入包含多条序列的 FASTA；
   - 选择需要的评分方法，对候选序列进行排序或筛选；
   - 用户可以在结构预测前筛选以减少计算，也可以在得到结构后按结构相关分数再次筛选；
   - 用户查看候选序列、结构和分数，并导出选中的结果。
2. **ESM-3 ProteinPrompt 设计、生成、重折叠和结构一致性筛选**
   - 用户可以从空白、序列、PDB 或已有 ProteinPrompt 开始，不要求必须具有模板 PDB；
   - 用户在 Prompt Studio 中编辑项目自己的完整 ProteinPrompt，并用 ESM-3 生成候选；
   - 用户对候选进行评分和筛选，再选择 SimpleFold、ESMFold2 或其他结构预测模型重折叠同一批序列；
   - 用户比较 ESM-3 结构与重折叠结构，继续筛选并导出结果。
3. **ESM-3 结构生成、ProteinMPNN 反折叠和再次折叠**
   - 用户以同样的 ProteinPrompt 入口创建并运行 ESM-3 生成；
   - 用户筛选结构候选，再使用 ProteinMPNN 为选中结构设计子代序列；
   - 用户使用结构预测模型折叠子代序列，继续评分、筛选和比较；
   - 结果界面保留父结构、子代序列和再次折叠结构之间的来源关系，并允许导出选中结果。

三个场景中的节点、模型、评分和筛选都可以由用户增删、替换或重新连接。界面不得把场景包装成
隐藏过程，也不得因默认模板而限制用户自行搭建空白流程。

## 2. Workflow 节点画布

画布区分三种 authoring 角色：ordinary Node、specialized composition 和 managed member。普通
Palette 只显示 ordinary Nodes 和一个“编写 ProteinPrompt”specialized entry。Prompt composition
内部的 managed members 仍显示在 materialized Workflow 中供只读检查，但不能从 Palette 单独添加、
不能通过通用参数表单修改，也不能脱离 composition 单独删除或复制。

### 2.1 Blender 风格的节点卡片

- 本节的通用参数编辑规则适用于 ordinary Nodes；specialized composition 从专用入口编辑，managed
  members 只读显示。
- 参数直接在节点卡片内部编辑；右侧全局参数面板不是主要编辑入口。
- 节点内部参数按功能分组。
- 打开流程时，所有参数分组默认收起。
- 每个参数分组可以独立展开或收起。
- 节点整体也可以进一步收起。
- 节点整体收起后只显示节点名称。
- 唯一已确认的例外是流程运行期间：名称旁可以显示运行状态，但节点仍不自动展开。
- 节点内可以使用数值框、滑杆、开关、下拉菜单等控件；科学单位直接显示在数值旁。

### 2.2 添加与查找节点

用户可以通过两种方式添加节点：

1. 从左侧节点列表拖入画布；
2. 在画布空白处打开搜索菜单，搜索并添加节点。

左侧节点列表支持两种分类方式：

- 按研究用途分类，例如输入、Prompt、生成、折叠、评分、筛选和导出；
- 按软件模块或模型提供方分类。

同一时间只显示一套分类，用户可以切换；搜索覆盖全部 ordinary Nodes 和 specialized entries，
不返回 managed members。

### 2.3 连接与断开

- 用户从输出端口拖出连线，放到另一个节点的输入端口完成连接。
- 拖动连线时高亮能够接受该连接的输入端口。
- 不兼容的输入端口不接受放置。
- 用户可以选中连线后按 Delete/Backspace 断开。
- 用户也可以从已连接的输入端口把连线拖到画布空白处断开。
- 当一个只能接受单一连接的输入端口已经被占用时，新连线自动替换旧连线，不弹出确认窗口。

### 2.4 删除节点与撤销

- 用户可以选中一个或多个节点，按 `Delete/Backspace` 立即删除。
- 删除节点时不显示确认窗口。
- 与被删除节点相连的全部连线同时删除。
- 用户可以用 `Ctrl/Cmd+Z` 撤销节点删除，并恢复节点及其连线。
- Workflow 画布保留连续、多步的编辑撤销记录。
- 添加、删除或移动节点，连接或断开连线，修改参数以及切换模型都可以逐步撤销。
- `Ctrl/Cmd+Z` 始终撤销最近一次画布编辑，不仅限于删除操作。
- 删除“编写 ProteinPrompt”specialized composition 会整体删除其 managed members；managed member
  不能单独删除。

### 2.5 复制流程片段

- 用户可以选中一个或多个节点进行复制和粘贴。
- 副本保留所选节点及其当前参数。
- 如果一条连线的两端都在所选节点中，该内部连线随节点一起复制。
- 所选节点与未选中节点之间的外部连线不复制。
- 粘贴得到的流程片段可以独立移动、编辑和重新连接。
- 复制 specialized composition 会产生新的完整 composition identity；managed member 不能脱离
  composition 单独复制。

### 2.6 科学操作与模型选择

画布节点表达“要进行什么科学操作”，具体模型在节点内部选择。

例如，画布上只有一个“预测蛋白质结构”节点；节点内的模型下拉菜单可以选择 `SimpleFold`、`ESMFold2` 或其他可用结构预测模型，而不是为每个模型建立一个独立节点。

模型切换规则：

- 新增节点时自动选择一个推荐模型，并明确显示当前选择。
- 切换模型时保留模型之间共有的参数。
- 每个模型分别记住自己的专属参数；切回模型时恢复之前填写的值。
- 已保存流程中的模型选择绝不自动更改。
- 如果保存的模型当前不可用，节点保留原选择并明确标记无法运行及原因；只有用户主动选择其他模型后才发生改变。

推荐模型的具体判定规则尚未裁决。

### 2.7 原型 1 验证决定：采用空间画布卡片方案

2026-08-29 的“默认流程与 Blender 节点画布”原型验证决定采用方案 A，作为后续正式界面设计的结构方向：

- 保留自由空间布局的 Workflow 画布；
- 左侧持续显示可切换分类方式的 Node Type 列表；
- Node Instance 使用常规空间卡片，Port 位于卡片两侧；
- 模型选择、Port 和默认收起的参数组在同一节点卡片内形成清楚的纵向层级。

方案 B 的“数据类型主轴”和方案 C 的“实验仪器面板”不再作为后续正式界面的整体结构方向。
本次选择不裁决连线是否长期显示 Port Type 标签，也不裁决最终颜色、图标、分类名称或视觉密度；这些仍属于后续视觉验证。原型代码仍是一次性验证材料，不成为生产实现基线。

## 3. ProteinPrompt Studio

### 3.1 产品边界

Prompt Studio 编辑项目自己的 `ProteinPrompt`，不直接编辑或照抄任何 provider SDK 的 Prompt 格式。

当前项目拥有的完整内容是：

- sequence track；
- structure coordinate track；
- secondary-structure track；
- absolute per-residue SASA track，单位固定为 Å²；
- function annotation interval collection。

`ResidueLayout` 是后端用于对齐这些内容的内部科学身份轴，不是用户可编辑的 `ProteinPrompt`
内容类型，也不得作为字段、轨道或编辑控件暴露在前端。前端可以显示便于定位的链与残基位置，
并提供新增、删除等残基操作；具体科学身份及各轨道重新对齐由后端维护。

Prompt Studio 始终允许表达项目定义的完整 `ProteinPrompt`。连接到具体模型后，界面再显示该模型能否使用这份 Prompt；模型不兼容时禁止静默删除、修复或更改用户内容。

“生成哪条轨道、使用哪个模型、执行多少步”不是 `ProteinPrompt` 字段，属于后续科学操作节点。

### 3.2 打开方式

- Workflow 中的“编写 ProteinPrompt”specialized composition 提供“编辑 ProteinPrompt”入口。
- 点击后进入占据主要界面的专用 Prompt Studio，而不是把完整编辑器塞入节点卡片。
- 用户保存或取消后返回原节点画布。

### 3.3 四种同等级入口

Prompt Studio 不以模板 PDB 为前提，提供四种同等级入口：

1. **新建空白 Prompt**：用户指定单链或多链，以及每条链的长度；所有轨道初始为未指定，后端建立内部科学身份轴。
2. **从序列开始**：用户粘贴或上传 FASTA，并填入 sequence track；内部残基对应由后端建立。
3. **从结构开始**：用户上传 PDB 并选择链，填入相应的 sequence 和 coordinates；内部残基对应由后端建立。
4. **打开已有 ProteinPrompt**：完整恢复所有可编辑轨道和功能注释；内部残基对应由后端恢复。

入口只决定初始内容，不限制后续编辑能力。

### 3.4 工作区布局

Prompt Studio 使用三个同步区域：

- 左侧：三维蛋白质结构；
- 下方：按同一组残基位置对齐的 ProteinPrompt 残基矩阵；
- 右侧：当前所选残基或区间的联合编辑工具。

残基矩阵规则：

- 每列显示一个可定位的链与残基位置；前端不显示或编辑内部 `ResidueLayout` 对象。
- sequence、coordinates 状态、secondary structure 和 SASA 按行对齐显示。
- function annotations 以跨残基区间的 ribbon 显示，而不是伪装成普通 nullable scalar track。
- 所有轨道同时属于同一个视图；用户可以收起或隐藏暂时不需要的行，但不会被拆成互不关联的页面。
- 多链边界、gap、新增和删除必须可见。

没有结构坐标时，三维区域自动收起，把空间让给残基矩阵；添加、导入或生成坐标后再显示。界面不构造虚假的临时结构。

### 3.5 残基选择与同步

用户可以选择：

- 单个残基；
- 一个连续区间；
- 多个不连续区间。

三维结构、残基矩阵和右侧联合编辑面板保持双向同步。多个相距较远但共同组成一个科学区域的残基可以作为一个选择集合操作。

### 3.6 联合编辑与变化状态

选中残基后，右侧在同一个面板中同时显示 sequence、coordinates、secondary structure、SASA 和 function annotations。用户可以组合修改多项内容，先预览，再一次应用。三维视图的 hide/show 只改变 opaque UI state；只有清除 coordinate value 才会移除该残基的 Prompt-side coordinate value。连接 ESM-3 时，兼容性和 effective-input preview 只显示 atom37 投影；非 atom37 原子保留在 ProteinPrompt 中但不影响 ESM-3 provider input。

从 FASTA、PDB 或已有 ProteinPrompt 开始时，编辑器区分：

- 来源中的原始值；
- 明确保留且与来源相同的当前值；
- 用户修改后的值；
- 已清除或设为未指定的位置；
- 新增残基；
- 待删除残基。

协议对应的六态为 `source`、`current`、`changed`、`cleared`、`inserted` 和
`pending-delete`。

所有轨道使用一致的变化标记，并支持撤销。

删除来源残基并应用局部 preview 后，当前 ProteinPrompt 的有序残基投影立即排除该残基，
但 Prompt Studio 的残基矩阵必须把原来源 locator 作为只读 `pending-delete` 删除证据继续显示，
并以明确的颜色或划线与当前残基区分。该证据不计入当前残基数，不能继续作为当前残基编辑；
撤销删除时恢复为当前残基，确认 `apply(replace)` 写回 Workflow Draft 后随本次 session tombstones
一起清除。删除本次 session 新增、因而没有来源对应的残基时，不创建 `pending-delete` 证据。

### 3.7 完整残基操作模型

残基编辑分成“新增或删除残基”和“改变残基上的条件”两类。前端以领域操作表达前者，
不提供 `ResidueLayout` 字段或布局对象编辑器。

| 操作 | 残基是否保留 | 对 ProteinPrompt 的影响 |
|---|---:|---|
| 新增（指定 / Mask） | 新增 | 在指定位置新增残基；科学身份由后端创建。新增操作必须明确选择“指定”或“Mask”，同一次预览列明指定值与处于 Mask 的轨道 |
| 删除残基 | 删除 | 删除指定残基；后端同步重新对齐各轨道，并预览受影响的功能注释 |
| 指定 | 保留 | 为所选残基在一个或多个轨道上设置明确值 |
| Mask/清除 | 保留 | 将用户选中的轨道设为未指定；不自动清除其他轨道 |
| 保留 | 保留 | 批量编辑时明确保留当前值不变 |

残基操作只接受以上五类：保留、指定、Mask、新增（指定 / Mask）和删除。“恢复来源值”不是残基操作。撤销属于 Prompt Studio 的编辑历史操作，不增加另一种残基操作类型。

Function annotations 通过添加、修改、删除或拆分区间处理，不使用逐残基 `null` mask。

残基选择可以是：

- 用户明确选中的残基集合；
- 可复现随机选择：用户提供数量、允许范围和随机种子。

随机 Mask 或随机新增 Mask residues 时：

- 先在残基矩阵和三维视图中显示实际选中的位置；
- 同时显示数量、允许范围和种子；
- 用户可以更换种子重新抽取；
- 只有用户确认后才应用。

### 3.8 三种编辑模式

同一个 Prompt Studio 提供三种明确模式：

1. **布局模式**：新增、删除残基，编辑链与残基轴；
2. **条件模式**：对一个或多个轨道执行保留、指定和 Mask；
3. **结构模式**：在三维视图中以残基为单位编辑结构坐标。

切换模式不会隐藏其他轨道，只会改变当前可执行的操作和快捷键。

默认模式：

- 新建空白 Prompt 进入布局模式；
- 从 FASTA、PDB 或已有 ProteinPrompt 开始时进入条件模式；
- 不根据用户上一次使用状态改变默认模式。

整个 Prompt Studio 采用 Blender 风格的选择、快捷键、确认、取消与撤销习惯。所有快捷操作也必须能从可见按钮或菜单完成，不能要求用户记住快捷键才能使用功能。

残基矩阵的键盘契约冻结如下：

- 点击可编辑单元格后建立明确的键盘焦点；方向键在当前残基轴和可见轨道之间移动焦点。键盘焦点与残基选择分别可见，移动焦点时默认把选择收敛到新焦点残基。
- Sequence 接受标准单字母氨基酸代码。焦点残基属于多选时，同一个字母应用于全部选中残基。字母 `I` 始终表示 isoleucine，不承担插入命令。
- Coordinates 使用 `Space` 在 Assigned 与 Mask 之间切换。Assigned → Mask 总是可以进入预览；Mask → Assigned 只允许恢复当前编辑 session 中仍保留的精确原始 coordinates。完成 `apply(replace)` 或重新打开后，如果来源本身是 Mask，则不能用快捷键凭空恢复坐标，必须从结构或其他明确来源重新指定。
- Secondary structure 接受冻结的 SS8 字符 `H/B/E/G/I/T/S/-`。
- SASA 接受大于或等于 0 的数字或小数，编辑器持续显示固定单位 Å²。
- 在已有 Function ribbon 上输入时，编辑完整 `(label, start, end)` tuple 的 `label` 并保持原 endpoints；旧 source tuple 进入 `pending-delete`，新 tuple 为 `inserted`。在空白位置输入前，必须先选择同一 chain 的连续区间作为 endpoints。Function 不退化为逐残基字符串编辑。
- `+` 在键盘焦点残基之后建立插入草稿。数字设置插入数量；单个氨基酸字母可应用于全部新增残基；粘贴多字母序列时长度必须与数量一致。未输入 Sequence 时新增残基的 Sequence 为 Mask，Coordinates、SS8、SASA 和 Function 均为 Mask / 未指定。多选时只在键盘焦点锚点之后插入一次。opaque residue handles 仍只由 backend Preview 分配。
- 用户操作立即建立并持续更新唯一的未应用 Preview，不存在独立“键盘草稿 → 请求 Preview”步骤，也不提供“预览指定 / 预览删除 / 预览插入”等按钮。`Backspace` 修改当前输入，`Enter` 应用已通过 diagnostics 的 Preview，`Esc` 取消 Preview，`Cmd/Ctrl+Z` 撤销已应用编辑。存在局部 Preview 时不能保存。
- 快捷键对应的直接操作必须继续提供可见按钮或菜单入口。

矩阵决定当前轨道上下文，右侧不重复提供 SEQ / XYZ / SS8 / SASA / FUNC 标签组。Sequence 行内的指定、Mask、插入和删除保留为当前局部操作的入口与状态参考；触发后立即显示矩阵差异和右侧影响范围。右侧在空闲时只解释当前操作，在 Preview 状态只显示参数、影响、diagnostics、应用和取消。

顶部主操作显示为“保存”。点击保存时系统自动请求 normalized backend Preview，再显示最终确认；用户不需要先选择“Preview 保存”。

六态说明默认收进矩阵控制条中的“状态图例”披露控件；选择摘要由上方选择条承担，不在矩阵底部重复。矩阵表面按轨道内容高度收拢，不为图例或重复选择文本保留整块空白区域。

### 3.9 残基布局变化

- 用户可以在已经填写轨道内容后继续增加或删除残基、区间或链。
- 所有轨道根据残基身份同步重新对齐。
- 新增位置必须在预览中明确标为指定或 Mask；没有指定值的轨道为 Mask。
- 删除前必须预览将丢失的轨道值和受影响的功能注释。
- 用户确认后，布局与所有轨道作为一个整体变化。

### 3.10 导入、合并与手动对齐

用户可以向已有 ProteinPrompt 继续导入 PDB、另一份 ProteinPrompt 或其他残基数据。

合并行为：

- 先显示统一合并预览；
- 按轨道和残基展示新增、保留、替换和冲突；
- 用户选择需要采用的部分后统一应用；
- 不使用固定的“全部覆盖”或“只填空白”规则。

当新来源与当前 Prompt 的长度、缺失区间或残基编号不同：

- implementation 可以提供明确标记为未确认的临时对齐草稿，但不得按数组位置猜测科学对应；
- 临时草稿不会直接成为最终科学对应关系；
- 用户必须手动调整并确认；
- 手动对齐同时提供上下序列的可视化对齐视图和精确的残基对应表；
- 用户可以插入 gap、移动区间或重新指定来源残基到目标残基的对应；
- 两种对齐视图同步更新。

### 3.11 结构模式

结构编辑的最小单位是残基，不支持单原子选择或单原子坐标编辑。

- 选中一个残基时，其全部原子坐标作为整体移动。
- 选中连续或不连续的多个残基时，将整个选区视为一个刚性整体，保持选区内部所有残基和原子的相对几何关系。
- `G` 用于移动，`R` 用于旋转。
- 支持 Blender 风格的 `X/Y/Z` 轴约束、确认、`Esc` 取消和 `Ctrl/Cmd+Z` 撤销。
- 不支持 `S` 缩放。
- 操作结果按用户指定的精确刚体变换保存。
- 不自动优化附近残基，也不自动移动邻近残基。
- 选区边界可能出现不连续时只做明确标记；自动结构优化属于独立科学操作。

### 3.12 保存、取消与完整性检查

- Prompt Studio 使用明确的“保存 ProteinPrompt”和“取消”。
- 编辑过程中不会自动写回 Workflow。
- 关闭时如有未保存修改，用户必须选择保存、放弃或继续编辑。
- 缺少某些轨道或某些位置未指定是合法状态。
- 残基与各轨道无法对齐、轨道长度错误、功能区间越界等项目格式错误会阻止保存。
- 一次显示全部格式问题，并允许点击定位到对应残基或区间。
- 不自动删除、填充或修复科学内容。
- 模型兼容性问题不阻止保存 ProteinPrompt，只影响后续模型节点能否运行。

Prompt Studio 始终显示一个整份 Prompt 摘要：

- 链与长度；
- 各轨道已指定/未指定数量；
- function annotations 数量；
- 项目格式问题；
- 当前连接模型的兼容性。

### 3.13 原型 2 验证决定：采用矩阵优先的残基账本方案

## 4. Workflow 运行

### 4.1 运行范围

用户可以：

- 运行完整流程；
- 运行到所选节点；
- 从所选节点继续运行。

局部运行时，画布明确高亮本次会执行的节点范围。

### 4.2 运行前确认

运行不会立即开始。界面先显示运行摘要：

- 执行范围；
- 使用的模型；
- 主要参数；
- 生成数量；
- 随机种子；
- 当前阻止运行的问题。

用户确认后才开始。问题可以直接定位到相关节点或 ProteinPrompt 内容。

### 4.3 运行状态

- 收起的节点保持收起。
- 节点名称旁显示等待、运行中、成功、失败或取消状态。
- 点击状态可以查看该节点的运行详情。
- 不自动展开正在运行的节点。

### 4.4 失败行为

- 一个节点失败后，与它无依赖关系的其他分支继续运行。
- 依赖失败节点的后续节点明确标记为未执行。
- 用户修正问题后可以从失败节点继续运行，不必重跑已完成且未受影响的部分。

### 4.5 取消运行

- 用户只能取消整次运行，不提供取消单个节点的操作。
- 取消整次运行后，所有正在运行或等待运行的节点停止。
- 取消前已经完成的节点结果继续保留，并允许用户查看。
- 取消运行不会删除已经产生的候选、分数或结构结果。

### 4.6 最近一次运行

- 每个项目只向用户显示最近一次运行。
- 用户重新打开项目时，运行状态和 Results Workbench 都对应最近一次运行。
- 界面不提供以前运行的历史列表。

### 4.7 原型 6 验证决定：采用空间范围叠层方案

2026-08-30 的“运行范围、状态、失败与取消”原型验证决定采用方案 A“空间范围叠层”，作为后续正式界面设计的 Workflow 运行范围与生命周期表达方向：

- 在原型 1 已采用的自由空间 Workflow 画布上直接高亮本次执行范围，不切换到独立运行页面或以表格取代画布；
- 收起的 Node Instance 保持收起，并在名称旁持续显示等待、运行中、成功、失败或取消状态；
- 运行范围选择、运行操作、当前 Node Instance 运行详情与最近一次 Run 事件组织在画布相邻侧栏；
- 失败节点、因上游失败而未执行的下游、继续运行范围和整次取消后的节点状态仍直接回到同一画布空间表达；
- 当前 Workflow 与最近一次 Run 使用的 Workflow 不一致时，“来自修改前的流程”标记同时伴随画布结果入口与 Results Workbench。

方案 B“运行账本”和方案 C“分支泳道”不再作为后续正式界面的整体结构方向，只保留为一次性比较证据。本次选择不裁决最终颜色、图标、视觉密度、进度与耗时表达、运行详情中的 evidence 深度、“无成功上游时从节点继续”的入口行为，或是否区分“运行中被取消”和“等待中被取消”。完整一次性比较材料捕获在 `codex/prototype-6-run-lifecycle` 分支；原型代码不成为生产实现基线。

## 5. Results Workbench

### 5.1 默认布局

结果工作区同时显示：

- 候选蛋白质表格；
- 三维结构查看器；
- 当前候选的序列、分数、来源关系和亲子关系。

三个区域保持同步。

如果用户在最近一次运行后修改了节点参数、模型或连线，但尚未重新运行：

- Results Workbench 继续显示最近一次运行产生的结果；
- 界面必须明确标记这些结果“来自修改前的流程”，不得让用户误认为它们对应当前流程；
- 用户仍然可以查看、比较、筛选和导出这些旧结果；
- 下一次运行产生结果后，由新的最近一次运行结果替代当前显示内容。

### 5.2 多候选比较

- 用户可以选择多个候选，并排比较结构、序列和分数。
- 如果 Workflow 已经产生结构对齐结果，可以叠加查看。
- 临时视觉叠加不冒充新的结构对齐科学计算。
- 不把全部候选默认叠加到一个三维视图。

### 5.3 临时筛选与流程筛选

- 结果表格中的排序和筛选默认只影响当前视图。
- 临时筛选不会自动修改原 Workflow。
- 用户点击“保存为流程筛选”后，画布中生成一个可编辑的筛选节点。

### 5.4 直接导出

- 用户可以直接导出当前勾选的候选，不要求先把筛选保存回 Workflow，也不要求重新运行。
- 导出固定生成一个 ZIP，不显示格式选择窗口。
- ZIP 包含：
  - 每个候选的 PDB 结构；
  - 所有候选的 FASTA 序列；
  - 分数 CSV；
  - 记录候选身份、来源关系和运行信息的说明文件。

### 5.5 原型 7 验证决定：采用谱系工作台方案

2026-08-30 的“Results Workbench 与候选关系”原型验证决定采用方案 B“谱系工作台”，作为后续正式界面设计的 Results Workbench 整体信息结构方向：

- 父结构 Candidate → ProteinMPNN 子代序列 Candidate → 再次折叠结构 Candidate 构成主要科学来源轴，以稳定身份、角色和 Method 明确表达亲子关系；
- 候选表格保留为相邻账本，用于聚焦 Candidate、排序、临时筛选和勾选比较 / 导出集合，不再作为压过谱系的整体主轴；
- 当前 Candidate 的结构、序列、分数和来源 dossier 与谱系主轴保持相邻并同步；
- 多 Candidate 并排与使用已有 Structure Alignment Evidence 的叠加继续明确区分，比较和导出使用同一个明确勾选集合；
- 临时表格筛选、保存为 Workflow 筛选、来自修改前 Workflow 的 Results 提示和固定 ZIP 导出来源继续伴随相关操作显示。

方案 A“候选账本”和方案 C“审阅篮”不再作为后续正式界面的整体结构方向，只保留为一次性比较证据。本次选择不裁决默认 Metric、Metric Definition、显示方向与单位、默认比较数量、最终三维布局、“保存为流程筛选”的表达能力、最终颜色或视觉密度。完整一次性比较材料捕获在 `codex/prototype-7-results-workbench` 分支；原型代码不成为生产实现基线。

## 6. 项目保存与管理

### 6.1 自动保存与版本

- 个人流程的当前修改自动保存。
- 用户可以随时创建有名称的版本，例如“第一次生成参数”或“调整 Prompt 后”。
- 版本包含节点流程、参数、ProteinPrompt 和画布布局。
- 用户打开较早命名版本并继续修改时，从该版本创建新的编辑分支。
- 原版本和打开旧版本前的当前工作都保留，不发生覆盖。

### 6.2 项目菜单

项目菜单提供以下个人项目操作：

- 新建；
- 搜索；
- 打开；
- 重命名；
- 复制；
- 删除。

首批产品不提供项目文件夹、标签或收藏功能。

复制项目时：

- 新项目只复制当前的节点流程、参数、ProteinPrompt 和画布布局；
- 不复制原项目的命名版本；
- 不复制原项目最近一次运行的状态或结果；
- 新项目作为独立、尚未运行的实验分支打开。

删除项目时：

- 完整项目先进入“最近删除”，而不是立即永久删除；
- 用户可以从“最近删除”恢复项目；
- 用户也可以在“最近删除”中再次选择永久删除。

### 6.3 原型 8 验证决定：采用上下文画布方案

2026-08-31 的“项目、自动保存与命名版本”原型验证决定采用方案 A“上下文画布”，作为后续正式
界面设计的项目信息结构方向：

- Workflow 画布继续作为项目的主要工作表面；
- 当前项目身份、自动保存状态和版本来源持续伴随画布显示；
- 项目库按需从侧边打开，不长期压缩 Workflow 画布；
- 默认示例首次修改、Prompt Studio 明确保存、命名版本分支、项目复制与最近删除恢复都回到同一
  项目上下文中表达；
- 版本关系用于解释当前工作的来源，不把 Workflow 降为版本时间线的附属预览。

方案 B“版本时间线”和方案 C“实验项目库”不再作为后续正式界面的整体结构方向，只保留为
一次性比较证据。本次选择不裁决旧命名版本分支的最终命名与导航、项目默认排序、最终颜色、
图标或视觉密度；原型代码不成为生产实现基线。

## 7. 用户旅程基线

后续功能设计必须至少保持以下旅程成立：

1. 启动后直接看到默认 PDB → ProteinPrompt → ESM-3 → 评分 → 筛选流程，无教程遮罩。
2. 修改默认示例时无感创建个人副本，默认示例保持不变。
3. 从空白画布添加节点、拖拽连接、内嵌编辑参数并运行完整或局部流程。
4. 在没有模板 PDB 的情况下创建空白、多链 ProteinPrompt，并完整编辑项目拥有的所有轨道。
5. 从 FASTA、PDB 或已有 ProteinPrompt 开始，导入第二来源，手动确认残基对齐后合并。
6. 对明确或可复现随机选择的残基执行保留、指定、Mask、新增（指定 / Mask）和删除，并预览所有受影响轨道。
7. 在结构模式中以残基集合为刚性整体移动或旋转，不进行原子级编辑、缩放或隐式优化。
8. 保存稀疏但格式合法的 ProteinPrompt；格式错误可定位，模型不兼容不会损坏 Prompt。
9. 运行失败后独立分支继续，修正后从失败节点继续。
10. 在 Results Workbench 中比较多个候选、临时筛选、选择结果并导出固定 ZIP。

## 8. 延后处理的界面细节

以下事项不影响已经确认的核心用户流程，本轮不再继续讨论。它们可以在后续视觉设计或实际
可用性验证时处理，但不得改变本文已经确认的功能基线：
