# 10 — Candidate system and selection modules

**What to build:** A user takes scored candidates, filters out those below a TM-score threshold, sorts the remainder by a weighted combination of TM-score and secondary structure agreement, selects the top 10, and inspects the lineage of the winning candidate to see it was generated by ESM3, redesigned by ProteinMPNN, and folded by ESMFold2. The candidate viewer shows this full history.

**Blocked by:** 09 — Scoring: alignment, metrics, DSSP, and agreement.

**Status:** ready-for-agent

- [ ] `Candidate` dataclass: candidate_id, data_ref (reference to the underlying sequence or structure), parent_ids (list of upstream candidate IDs), metadata (dict with sample_index, model_name, etc.).
- [ ] `CandidateCollection` dataclass: collection_id, item_type (protein.sequence or protein.structure), items (list of Candidate references). Iterable and filterable.
- [ ] `Filter Candidates` module: input = `candidate.collection` + `score.collection`, output = `candidate.collection`. Module parameter: conditions list — each with `score` (score_id), `operator` (>=, <=, >, <, ==, !=), `value` (float). Candidates whose scores don't satisfy ALL conditions are removed.
- [ ] `Sort Candidates` module: input = `candidate.collection` + `score.collection`, output = `candidate.collection`. Module parameters: `score` (score_id), `order` (ascending/descending). Sorts candidates by the specified score.
- [ ] `Top-K` module: input = `candidate.collection`, output = `candidate.collection`. Module parameter: `k` (int, min 1). Keeps the first K candidates after sorting.
- [ ] `Weighted Rank` module: input = `candidate.collection` + `score.collection`, output = `candidate.collection`. Module parameter: `metrics` list — each with `score` (score_id) and `weight` (float, can be negative for minimization). Computes weighted sum, ranks candidates, appends a `weighted_rank` score entry.
- [ ] `Pareto Select` module: input = `candidate.collection` + `score.collection`, output = `candidate.collection`. Module parameter: `scores` (list of score_ids to consider). Returns non-dominated candidates (those for which no other candidate is better on all selected scores).
- [ ] `Diversity Select` module: input = `candidate.collection` + `score.collection`, output = `candidate.collection`. Module parameters: `k` (int), `diversity_score` (score_id to maximize spread on). Selects K candidates that maximize coverage of the score landscape, avoiding clusters of near-identical scores.
- [ ] UI: candidate viewer panel — list of candidates with expandable rows. Each row shows: candidate ID, item type icon, key scores (inline). Expand to see: full score list, metadata, parent candidates (clickable to navigate lineage).
- [ ] UI: lineage graph — interactive tree visualization showing a candidate's ancestors. Nodes are candidates (color-coded by source module). Edges show "generated by", "folded by", "scored by". Clicking a node selects that candidate.
- [ ] UI: sequence viewer — for sequence candidates, an interactive alignment-like view showing the amino acid sequence with residue indices. Multiple sequences can be loaded side by side for comparison. Highlight differences from a reference sequence.
- [ ] Tests: Filter removes candidates below threshold. Sort orders correctly ascending and descending. Top-K returns exactly K. Weighted Rank produces correct ordering for known weights and scores. Pareto returns only non-dominated candidates. Diversity returns K candidates with spread scores. Candidate lineage: parent_ids correctly reference upstream candidates. Candidate viewer renders without errors.
