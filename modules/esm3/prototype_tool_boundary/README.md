# 一次性原型：操作与工具的编译边界

问题：有序位置、序列条件、坐标条件交接给工具时，原生输入编译应由操作模块还是工具模块维护？两种路径能否正确处理编辑、工具能力差异和返回位置对应？

打开 `index.html` 即可操作，无依赖、网络、存储或服务。测试命令：

```sh
node --test modules/esm3/prototype_tool_boundary/prototype.test.cjs
```

## 比较对象

两种路径使用相同的正确原生编译规则。路径一由操作侧传入专用编译器、调用原生执行器并解码；路径二由工具实现内部编译、执行、解码，操作只调用任务约定。第二路径允许一个独立实现只依赖该任务约定；第一路径允许面向模型的操作完整暴露原生能力，但调用方承担模型专用知识。

ESM3 字段核对依据为固定上游的 `esm/sdk/api.py` 中 `ESMProtein`、`GenerationConfig`，以及当前模块 `adapters.py` 中 `protein_for` 的原子映射。当前工作树没有复制上游目录，核对使用原始项目的 `repositories/esm/`。坐标形状为 L×37×3，缺失值为 NaN；序列和二级结构使用 `_` 表示未知，SASA 未指定位置为 null。模型的实际分词、特殊 token、结构编码和推理仍属于 SDK；原型不模拟这些计算。

所有执行输出是模拟值。SparseSeq 是明确虚构的工具接口，只接受长度与零起点固定残基索引；输出故意采用逆序的显式位置索引，以检验解码对应。原型没有 ESM3 推理结论，也没有实验性设计结果。

## 本次公开任务约定

`TaskRequest = {task, frame, positions: [{key, source, condition}]}`

- `task` 为 `complete_sequence` 或 `generate_structure`。第二项仅生成结构轨道，不承诺补全序列。
- `positions` 数组是本次请求的完整有序位置。`key` 在本对象内唯一；增删由编辑模块先完成。它不是载体强制科学模型。
- `source` 是可选的真实链、编号和插入码；新位置为空。无需历史查询。
- `condition.sequence` 为明确的单残基或 null。观察值与是否作为条件分开。
- `condition.atoms` 只包含本次明确选用的具名原子及 XYZ；`frame` 明确它们所在坐标系。
- `condition.secondary` 与 `condition.sasa` 各自有空值，不凭其他轨道补齐。
- 输入只读。编译与执行后，所有原始观察值和条件保持不变。

`TaskResult = {task, simulated: true, positions: [{key, sequence | atoms}], frame?}`

- 公开结果按输入位置顺序接回。序列必须完成且满足固定条件。
- 结构任务检查每个位置具备本次约定要求的 N、CA、C 骨架原子；示例返回新坐标系。
- ESM3 示例按照该入口固定长度、保持顺序的约定解码；长度变化或形状错误拒绝。单靠长度相同不能证明未知工具保持顺序，新工具需要自己提供可靠对应规则。
- SparseSeq 返回零起点的显式位置索引，检查完整覆盖与唯一性后排序，再映射回输入位置键；缺少或重复对应拒绝。
- 工具不能支持某个条件时明确拒绝。用户可以修改输入条件；切换工具不会修改条件。

原生参数留在实现侧；示例固定显示 ESM3 的 track、num_steps 和 temperature，以便观察。正式接入仍需公开参数传递、文件所有权、取消和续算，本原型没有验证这些职责。

## 验证结论的边界

可直接测试：插删后的内容对应、两种边界结果一致、原生输入形状、只读输入、能力拒绝、原生输出对应错误、独立任务实现接入、同一 ESM3 实现复用两个任务。

尚需真实实验：ESM3 实际掩码行为与生成输出、第二个真实模型的条件交集、原生结构条件的语义保持、批次取消和续算、较大文件的交接。该演习不把两个任务约定定为全项目统一科学类。
